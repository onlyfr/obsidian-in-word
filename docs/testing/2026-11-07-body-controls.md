# 본문 편집 준비 시작 / 중지 검증

2026-11-07, 구현 계획 1단계. 네이티브 호스트가 명시적으로 주입된 환경에서 시작·중지와 문단 등록을 연결했다. MD 원본/Word 표현 자동 전환은 2단계이며 이번 UI는 본문을 다시 쓰지 않는다. 일반 웹 작업창에는 연결과 컨트롤이 없으며 설치형 호스트도 아직 제공하지 않는다.

## 구현

- `NativeBodyBridge`로 호스트·입력/선택 신호·연결 수명을 주입한다. 제품 진입점에는 localhost 검색이나 시험 HTTP 연결을 넣지 않는다. 모듈은 연결 주입 후 지연 로딩한다.
- 시작은 실제 입력 idle과 선택 지원을 확인한 뒤 일반 문단을 등록한다. 기존 소유 문단은 재사용하고, source 상태나 미완료 전환 기록은 읽기만 하고 거부한다.
- 중지는 후속 작업을 취소하되 이미 제출된 등록 결과를 기다린다. 결과를 모르면 재전송하지 않고 오류와 Word Ctrl+Z 안내를 유지한다. 연결 정리는 클라이언트 lease만 해제한다.
- 실제 입력 unknown/조합 중에는 대기한다. 반복 health 신호로 문서를 조회하거나 상태 안내를 계속 갱신하지 않는다.

## 검증 결과

- `npm test`: 31개 파일, **520건 통과**.
- `npm run build`: 타입체크와 프로덕션 빌드 통과. 본문 컨트롤 청크 15.67 kB / gzip 5.65 kB. 제품 번들에 시험 RPC 경로가 포함되지 않음을 확인.
- `npm run test:word -- --body-controls-only`: 실제 Word에서 모두 통과. 증거: `test-docs/word-host/20261107-194915-60fa4a/body-controls-summary.json`.
  - 연결 주입만으로 등록하지 않으며 시작 후 등록, 중지, 같은 문단 재시작 시 중복 등록 없음.
  - 실제 네이티브 관찰기를 종료하면 오류로 중지하고 lease를 정리. 새 관찰기/epoch로 재연결.
  - 두 번째 문단 등록이 실제 완료된 뒤 응답만 지연시키고 중지: 결과를 기다리고 후속 조회·재등록 없음.
  - 세 번째 문단 등록 요청 뒤 중지하고, 완료된 요청의 응답을 의도적으로 끊음: 요청 1회, 오류·Ctrl+Z 안내 유지, lease 종료. 자동 재전송 없음.
  - 원문·문단 서식 유지. source/render/rollback 요청 없음. 공급자 제거 시 컨트롤 숨김.
- 기존 선택/경합/소유권/저장·재열기 회귀 통과: `test-docs/word-host/20261107-193502-4203c9/native-selection-summary.json`.
- 기존 설정 UI 회귀 통과: `test-docs/word-host/20261107-193714-f4f9c9/settings-ui-summary.json`. 닫기 포커스 검사는 고정 50ms 대신 실제 포커스 복귀를 기다리도록 수정.

중간 실행 `20261107-194749-2158eb`에서는 재시작 전 입력 신호가 unknown이 되어 대기한 채 검사 제한시간에 도달했다. 보호 조건은 유지했고, 독립된 재시작 시나리오 앞에 시험용 문단 선택 단계를 추가해 위 전체 실행으로 재확인했다. 입력 신호를 idle로 가정하거나 제품 RPC가 포커스를 가져오도록 바꾸지 않았다. 시험은 합성 문서만 사용하고 키 입력 없이 수행했으며 종료 시 전용 Word를 닫았다.

## 다음 순서

2단계는 등록한 문단의 진입/이탈에 MD↔Word 전환을 연결하고, 3단계는 실패·Undo 후 읽기 전용 상태 확인을 연결한다. 별도 복구 UI나 자동 롤백은 추가하지 않는다. 세부 항목은 `docs/implementation-plan.md`에서 관리한다.
