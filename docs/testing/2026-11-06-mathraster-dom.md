# 수식 래스터화기 DOM 하드닝 — 2026-11-06

`hardening/math-raster-dom`에서 로드맵의 다음 항목인 래스터화기 하드닝을 구현했다. 기준은 문서 보존 수정 및 Word 시험 도구가 있는 `8f21f46`이다.

## 변경

- 측정용 숨김 요소의 `innerHTML` 대입을 제거했다. MathML, 스타일, 래퍼, 기준선 탐침을 DOM 노드로 조립한다.
- `mathMLToElement`는 비활성 문서에서 파싱한 내용을 허용된 MathML 네임스페이스·태그·속성만 사용해 새 노드로 구성한다. 앞단 정제기가 정상 동작한다는 전제만으로 라이브 문서에 노드를 넣지 않는다. HTML/SVG 요소, 이벤트 속성, 링크, 이름공간 속성, 위험한 CSS 선언은 복사하지 않는다. 미리보기와 같은 허용 목록을 공유한다.
- SVG도 `createElementNS`로 만들고 `XMLSerializer`로 직렬화한다. CSS는 `textContent`로 넣어 `</style>`·`]]>` 등의 문자열이 마크업 경계를 만들지 않도록 했다. MathML 트리는 복제해서 쓰므로 HTML 재파싱이 없다.
- 기존 글자 크기·여백·3배 해상도·기준선 계산·폴백을 유지한다. 저장된 수식 그림의 렌더 버전도 유지한다.

## 검증

`npm test`: **386개 통과**(기존 372 + 신규 14). `npm run build`: 타입체크·프로덕션 번들 통과. 메인 번들은 **357.82 kB**, gzip **116.61 kB**로 같은 크기다. 증가는 지연 로딩되는 MathML/래스터화 모듈에 한정된다.

신규 단위 검사는 정제하지 않은 입력의 HTML/SVG·이벤트·링크 제거, 이스케이프된 마크업의 텍스트 보존, 잘못된 네임스페이스 거부, 실제 Temml 출력의 구조 보존, `innerHTML` setter를 금지한 렌더링, CSS 종료 문자열과 CDATA 문자열의 안전한 직렬화, 레이아웃 예외 시 측정 요소 제거를 확인한다. jsdom 검사에서는 레이아웃과 캔버스를 대체하고, 아래 실제 Word 검사에서 실제 결과를 확인한다.

실행: `npm run test:word -- --compare-raster-ref 8f21f46`

- 호스트: Windows Word **16.0.20527.20112**, 실제 Office.js PC 호스트.
- 박스 수식, 위/아래 주석 화살표, 취소선, 행렬, 합·분수·근호, HTML처럼 보이는 텍스트를 각각 인라인/독립 수식으로 렌더링: **총 12개 샘플의 크기·기준선·PNG 바이트가 변경 전과 전부 일치**했다.
- 비교는 같은 Temml/브라우저/수식 이미지 도우미를 사용하고, 변경 전 `mathraster.ts`만 가져와 측정·SVG 조립 경로를 비교했다. 과거 앱 전체/다른 브라우저와의 비교가 아니다.
- 혼합 문서 반복 적용, 누락 원본 차단, 실제 수식 삽입 실패, 알 수 없는 스타일, 세 종류의 실행 취소, 다른 영역의 오래된 수식 원본 보존도 다시 통과했다.
- 대형 합성 문서(Office.js 300문단, 표 30, 수식 60): 불러오기 **2.06초**, 적용 **3.64 / 3.59 / 3.65초**, 3회 모두 문단 텍스트와 객체 수 유지. 한 번의 로컬 측정이므로 성능 개선 주장에는 사용하지 않는다.
- Word 문서·서버·고유 GUID 임시 애드인 등록의 자동 정리까지 통과했다.

실행 증거는 gitignore 대상인 `test-docs/word-host/20261106-191147-390246`의 `results.jsonl`, `com-results.jsonl`, `summary.json`, `report.md`에 남아 있다. Mac/웹 Word, 모든 LaTeX 명령과 임의 외부 CSS의 안전성을 이 시험만으로 보증하지 않는다.
