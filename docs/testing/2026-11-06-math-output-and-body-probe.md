# 수식 출력 선택과 본문 편집 가능성 실험 — 2026-11-06

## 수식 출력 선택 (제품 기능)

작업창에 `Word 수식 우선 (기본)` / `모두 그림` 선택을 추가했다. 기본은 이전과 같은 OMML 우선 방식이다. 모두 그림 모드는 OMML 변환 가능 여부에 관계없이 마크다운 수식에 기존 PNG 렌더링·캐시·LaTeX 보존 경로를 사용한다. 설정은 애드인 출처의 localStorage에 저장하고, 저장소가 막혀도 현재 선택은 동작한다. Word 원본 보존 블록 안의 수식과 표 셀의 문자 `$…$`는 대상이 아니다.

개체 복원 전에 모드를 결정하며, 모두 그림 모드에서는 정상적인 사용자 선택임을 상태줄에 알린다. 그리기 실패는 기존처럼 경고와 소스 문자로 대체한다. 불러오기/적용 중에는 두 버튼과 수식 선택을 잠가 동시 실행을 막는다.

실제 Word에서 `x^2`, `\boxed{E=mc^2}`, 독립 `\frac{a}{b}`를 다음 순서로 시험했다.

| 단계 | Word 수식 | 수식 그림 | 확인 |
| --- | --- | --- | --- |
| 기본 혼용 | 2 | 1 | 기존 동작 |
| 모두 그림 | 0 | 3 | 모든 편집 가능 수식이 PNG |
| 모두 그림 재적용 | 0 | 3 | PNG 바이트와 문단 텍스트/개수 유지 |
| 불러오기 후 혼용으로 복귀 | 2 | 1 | LaTeX·인라인/독립 구분·문단 수 유지 |

Word가 이미지 앞뒤 공백을 NBSP로 표현할 수 있어 원본 마크다운 문자열 전체의 바이트 동일성은 주장하지 않는다. LaTeX와 표시 방식, 문단 수, PNG 바이트를 각각 비교했다.

추가로 **이미지만 있는 마지막 문단의 빈 문단 오판**을 수정했다. `Paragraph.text`가 비어 있어도 수식 그림이 있을 수 있었다. 이제 끝의 빈 텍스트 문단에 대해서만 `inlinePictures`를 기존 호스트 배치에 함께 로드하고, 그림이 있으면 빈 문단 수 계산을 멈춘다. 이로써 `getHtml`의 가짜 끝 문단이 마크다운 빈 문단 표지로 남아 모드 전환 때 문단을 늘리는 경로를 막았다. 추가 호스트 왕복은 없다.

## 본문 소스 전환 (개발용 실험)

제품 UI에 노출하지 않은 가능성 실험이다. 일반 문단 하나를 콘텐츠 컨트롤로 감싸 고유 ID로 추적하고, 공통 [DocumentSelectionChanged 이벤트](https://learn.microsoft.com/en-us/javascript/api/office/office.documentselectionchangedeventargs?view=word-js-1.2)를 구독했다. 이벤트는 키 입력을 가로채는 기능이 아니므로 본문 스니펫·IME 지원을 이 결과로 판단하지 않는다.

실제 Word `16.0.20527.20112`에서:

1. COM으로 문단 안으로 커서를 이동 → 본문이 `Probe target with **bold** text.`로 전환됐다.
2. COM의 Word Range 텍스트 편집으로 `Probe **edited** and _more_.`로 수정했다.
3. 다른 문단으로 이동 → 본문이 `Probe edited and more.`로 복원됐고, 다시 HTML을 읽으면 굵게·기울임을 가진 마크다운이 돌아왔다.
4. 최종 실행에서 선택 이벤트 2회에 변환은 진입/이탈 각 1회, 총 2회였고, 대기 후에도 되먹임 루프가 없었다. 옆 문단은 보존됐다. 종료 시 핸들러를 제거했다.

기존 `htmlToMarkdown`/`markdownToHtml`을 재사용했으며 제품의 전체 선택 영역 적용 함수를 그대로 자동 호출하지는 않았다. 지연 처리와 재진입 가드는 실험용이다. 한글 IME, 사용자 실제 타이핑, 빠른 문단 이동, 실행 취소·다시 실행, 콘텐츠 컨트롤 삭제, 애드인 중단/재로드, 공동 편집, 표·수식·필드가 든 블록, 커서 위치 보존은 정식 구현 전 별도 검증이 필요하다. 원본/소스 상태의 문서 내 복구 기록과 충돌 정책부터 설계한다.
