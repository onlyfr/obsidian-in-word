# 서식 왕복 중복 수정·네이티브 쓰기 가드 (2026-11-06)

## 서식 중복 수정

사용자가 확인한 `**굵게** → Word → ****굵게****`를 `<b><strong>굵게</strong></b>` 입력으로 재현했다. 기존 Turndown 경로는 중첩된 두 태그에 각각 구분자를 붙였다. 같은 문제로 기울임이 `__기울임__`으로 바뀌었고, 언어별로 나뉜 인접 굵은 run은 `**bo****한글****ld**`가 됐다.

공통 변환기에서 동등한 중첩 강조를 한 번으로 줄이고 인접한 같은 강조를 합친다. Word가 `<em><b>`와 `<strong><i>`를 번갈아 내보내는 경우도 굵게→기울임→취소선 순서로 정규화한다. 부분적으로만 강조된 텍스트의 경계를 옮기지는 않는다. Word 취소선은 `~~...~~`로 변환하고 글자로 입력된 물결표는 텍스트 이스케이프 단계에서 처리한다. 표 셀에도 같은 정리를 적용한다.

보존 객체를 먼저 사이드카에 저장한 뒤 변환 가능한 HTML만 정리한다. 변경 추적의 `<del>`을 취소선으로 취급하지 않으며, 변경 추적/객체 원본은 그대로 보존한다. 이미 `****굵게****`가 된 소스도 왕복하면 `**굵게**`로 정리된다. 이스케이프한 기호는 글자로 남는다. 목록의 들여쓰기 표준화와 기호 증식을 구분하며, 실제 시험에서는 목록 항목 2개가 유지됐다.

이 수정은 현재 제품 작업창에도 적용된다. 실험용 본문 코덱에 있던 별도 강조 정리를 공통 변환기로 통합해 중복 파싱과 구현도 제거했다.

## 네이티브 쓰기 가드 1단계

기존 관찰기에 일반 **소스 문단 하나만** 교체하는 별도 명령을 추가했다. Word UI 스레드에서 대상 문서 전체 경로, 고유 태그와 컨트롤 ID, 본문 story, 원문과 정규화한 WordOpenXML을 검사한다. 여러 문단·표·객체·필드·수식·변경 추적과 활성 변경 추적 모드는 거부한다. 모든 대상 조회를 마친 뒤 실제 TSF 상태와 관찰 순번, 요청 기한을 다시 확인하고 `Range.Text`를 한 번 설정한다.

요청은 실행별 epoch와 고정 크기의 UTF-16 패킷을 사용한다. 포인터나 실행 코드를 전달하지 않는다. 대기 중인 요청은 실행 전 취소/만료할 수 있다. 실행 중이거나 성공 여부가 불명확한 요청은 재시도하지 않는다. 이 요청은 로컬 파일과 명시적 네이티브 명령으로만 제출하며 SSE는 상태 관찰용이다.

**아직 전체 본문 편집 경로를 대체하지 않는다.** `WordBodyPort.source/render`, 선택 보존과 복구 저널을 이 명령에 통합하는 작업이 다음 단계다. 이 명령 자체의 호출 직전 검사는 네이티브에서 하지만 Word COM 내부 재진입까지 막는 TSF 잠금으로 검증한 것은 아니다. 기존 Office.js 렌더링이 원자적이 됐다고 주장하지 않는다.

API 근거: [Word Range.Text](https://learn.microsoft.com/en-us/office/vba/api/word.range.text), [Word 창의 Native Object Model 접근](https://learn.microsoft.com/en-us/windows/win32/api/oleacc/nf-oleacc-accessibleobjectfromwindow). 프로토콜과 결과 코드는 `native/word-ime/README.md` 참고.

- 실제 Word 서식 왕복 5회: `test-docs/word-host/20261106-212647-21ee95/format-summary.json`. 굵게·기울임·취소선·목록·한글/영문 조각이 동일한 마크다운으로 유지됐다.
- 실제 Word 전체 회귀: `test-docs/word-host/20261106-213346-d502df/report.md`. 보존·반복 적용·실패 경로·대형 문서·수식 모드·서식 왕복·본문 전환·복구/실행 취소/재열기 통과. 초기 실패에서는 옛 feasibility probe가 문단 끝 커서를 이탈로 판단해 즉시 렌더링하던 경계 분류를 바로잡았다.
- 네이티브 가드: `test-docs/word-host/20261106-213444-145e19/guard-summary.json`. 원문 충돌, 서식 충돌, ID 충돌, 다른 실행 epoch, 오래된 관찰 순번, 여러 줄, 변경 추적 활성, 입력 포커스 불명에서 거부하고 소스를 유지했다. idle에서는 `Alpha **guarded source** tail`로 한 번 교체됐다. MSVC `/W4 /WX` 빌드 통과.
- 실제 한글 조합 도중 차단도 확인했다: `test-docs/word-host/20261106-214947-8a1833/input-summary.json`. 실제 R/K 입력 후 TSF 조합이 활성인 동안 준비된 교체 요청을 제출하자 결과 코드 1(조합 중 거부), `NativeGuardBlockedActive=true`였다. 이어서 나머지 키와 Space를 입력해 `가나다`가 유지되고, 수동 idle 없이 문단 이탈 후 렌더링·커서 상대 위치 4 보존·단절 게이트가 통과했다. active/unknown 중 선택 조회는 0회였다. 외부 IMM32의 `ActualCompositionVerified=false`는 기존 관찰 방법의 한계이며, 별도 TSF OnEndEdit 조합 이벤트와 네이티브 차단 결과로 검증했다.

제품 메인 번들은 358.31 kB / gzip 116.80 kB, 변환기를 포함하는 Word 청크는 170.09 kB / gzip 68.11 kB다. 기존 사용자 문서는 수정하지 않았고 시험은 자체 문서에서 수행했다.
