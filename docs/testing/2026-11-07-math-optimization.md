# 수식 렌더링 최적화 1차

2026-11-07. 기준 커밋 `83a9d87`. 다음 기능 연결 전에 수식별 초기화와 실패 시 반복 로딩 비용을 점검했다.

## 변경

- MathJax의 TeX 글꼴 데이터(`TeXFont`)를 모듈당 한 번 생성하고 재사용한다. 이전에는 수식을 그릴 때마다 전체 글꼴 변형·문자·괄호 데이터를 다시 초기화했다.
- **TeX 입력기·SVG 출력기·문서 상태는 수식마다 분리**한다. 매크로·라벨·출력 캐시를 공유해 속도를 올리는 방식은 사용하지 않는다.
- 한 번의 적용에서 렌더러 모듈 로딩이 실패하면 다른 수식마다 같은 로딩을 반복하지 않는다. 해당 수식은 기존 정책대로 원본 소스와 경고로 남기고, 다음 적용에서는 다시 로딩할 수 있다.
- 출력이 같으므로 수식 이미지 캐시 버전 4를 유지한다. 불필요한 기존 이미지 재생성은 유발하지 않는다.
- 로컬 비교 스크립트와 실제 Word의 git 기준판 PNG 비교 경로를 정리했다. 기존 `--compare-raster-ref`가 MathJax 어댑터도 함께 과거 버전으로 읽고 `--math-only`에서도 작동한다.

## 측정

`npm run bench:math-svg -- 83a9d87`

Node `v24.19.0` / jsdom, 8종의 표현으로 만든 80개 수식, 워밍업 후 5회. 실행 순서를 번갈아 측정했다. SVG 생성·안전 필터·직렬화를 포함하며 PNG 래스터화나 Word 삽입 시간은 포함하지 않는다.

| 구간 | 기존 중앙값 | 변경 중앙값 |
| --- | ---: | ---: |
| 수식 80개 SVG 생성 | 330.00 ms | 262.14 ms |

이번 로컬 측정에서 약 **20.6% 시간 감소 / 1.26배 처리 속도**. 모든 SVG 문자열이 기준판과 동일했다. 환경·JIT·GC의 영향을 받는 한 시스템의 결과이며 문서 전체 적용 속도 향상률로 해석하지 않는다. 초기 모듈 다운로드/글꼴 최초 생성은 측정 범위 밖이다.

증거: `test-docs/math-bench/2026-11-07T11-34-16-507Z/summary.json` (폴더명은 UTC).

## 검증

- 단위 테스트 **528건**, 타입체크·프로덕션 빌드 통과. 정렬 환경·박스·취소선·SVG 필터·매크로 격리 유지.
- 렌더러 로딩 실패 회귀: 서로 다른 수식 2개에서 로더 1회 호출, 다음 적용은 다시 시도.
- `npm run test:word -- --math-only --compare-raster-ref 83a9d87` 실제 Word `16.0.20527.20150` 통과.
- **18개 이미지 PNG 바이트·크기·기준선이 기준판과 동일**. 기본 TeX 글리프, Word 수식/이미지 모드 전환, 원본 LaTeX 왕복·반복 적용 통과. 사용자가 제공한 7행 포함배제 공식의 등호 정렬도 유지.
- 이 Word 실행의 18개 래스터 관찰값은 기준판 145.1ms / 변경판 78.9ms. 기준판을 먼저 실행한 단일 관찰값이므로 일반적인 성능 향상률로 사용하지 않는다.
- 증거: `test-docs/word-host/20261107-203527-3b684c/math-summary.json`.
- 메인 JS 361.41 kB / gzip 117.92 kB 유지. 수식 이미지 지연 청크 1,672.36 kB / gzip 583.01 kB. 이번 변경은 CPU·초기화 할당량 개선이며 다운로드 크기 축소는 달성하지 않았다. Vite의 큰 청크 안내는 계속 발생한다.

다음 기능 순서는 구현 계획의 MD↔Word 연결, 실패·Undo 후 읽기 전용 확인을 유지한다. 큰 문서 전체 적용의 Office 왕복/삽입 비용은 별도 측정 대상이다.
