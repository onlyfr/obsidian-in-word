# 실패·Undo 이후 읽기 전용 상태 확인

2026-11-08. 구현 계획 2단계. 명시적인 네이티브 연결 환경에 **상태 확인**을 추가하고 시작 전 검사에도 같은 읽기 전용 경로를 적용했다. 본문 자동 MD↔Word 전환은 연결하지 않는다.

## 동작과 범위

- 실제 입력 idle과 네이티브 선택 신호를 기다린 후 선택한 소유 문단과 문서의 전환 기록을 읽는다. 등록되지 않은 선택은 그대로 보고하며, 상태 확인이 문단을 등록하지 않는다.
- 전환 기록의 형식·중복·버전과 미완료 phase/nativeStage를 검사한다. 기록이 참조하는 문단 모두에 대해 존재·epoch·소유 스냅샷·rendered 상태·지원 가능한 OOXML을 확인한다. 다른 문단의 미완료 기록도 새 등록을 막는다.
- 선택한 문단을 다시 읽어 ID·본문 리비전 변경을 확인하고, 기록과 선택이 바뀌면 검사를 거부한다. 확인 중의 선택 이동·입력 active/unknown·중지는 기존 게이트를 따른다.
- 결과는 시점별 확인이다. ‘확인 완료’가 이후 시작에 대한 영구 승인이 아니며 시작 시 다시 검사한다. 상태 확인 후 연결 lease는 종료한다.
- **등록·태그 수정·저널 저장·본문 복구·전환·불확실한 요청 재전송을 하지 않는다.** 문제가 남으면 오류와 Word Ctrl+Z / Ctrl+Y 안내를 유지한다.
- 현재 검사 범위는 선택한 소유 문단과 전환 기록이 참조하는 문단이다. 일반 Word 개체 전체를 검증하거나 원본을 자동 복원하는 기능은 아니다. 일반 웹 작업창에는 네이티브 연결이 없어 컨트롤이 숨겨진다. 설치형 호스트는 아직 제공하지 않는다.

## 검증

- 단위 테스트 **543건**, 타입체크·프로덕션 빌드 통과. 상태 확인 전후 무쓰기, 재시작 재검사, 다른 문단의 중단 기록·source/삭제/이전 epoch, 중복/불완전 기록, 검사 도중 본문·선택·기록 변경, idle 대기 중 취소 검증.
- 실제 Word `16.0.20527.20150`: `npm run test:word -- --body-check-only` 통과.
- 증거: `test-docs/word-host/20261108-122816-cf0ef4/body-check-summary.json`.
- 정상 등록 문단의 상태 확인은 본문/서식을 유지하고 lease를 닫았다. 등록되지 않은 영역 검사도 claim/transition 0회.
- 실제 한 글자 삽입을 Undo한 후 상태 확인, **Redo 1회로 삽입 복원 성공**. 읽기 전용 확인이 Redo를 지우지 않았다.
- 네이티브 원본 전환의 tagged 단계에서 실제 실패 주입. 상태 확인은 재전송 없이 거부. Undo 2회 후 원래 표시 텍스트가 복원됐지만 **source 태그가 남은 상태**에서도 거부했다. 이어서 **Redo 2회 성공**, 실패 직후 본문·태그가 동일하게 돌아왔다.
- 중단 기록이 남은 채 두 번째 일반 문단에서 시작해도 새 등록/본문 쓰기 0회. 자동 전환·복구 UI 없음.
- 중간 시험에서 Undo 직후 선택 위치와 이전 ‘확인 완료’ 표시를 읽는 타이밍이 드러났다. 시험은 Undo 뒤 대상 문단을 명시적으로 선택하도록 보완했고, 제품은 반복 확인 클릭 즉시 connecting 표시로 바꿔 이전 완료 상태가 남지 않도록 수정했다. 최종 전체 실행으로 확인했다.
- 본문 컨트롤 지연 청크 약 17.79 kB / gzip 6.28 kB. 메인 JS 361.46 kB / gzip 117.92 kB. 기존 큰 수식 이미지 청크 안내는 유지된다.
