# Windows 앱 1차 통합

2026-11-08. 사용자 결정: 우선 Windows 앱 하나만 만든다. 기준 `84e856c`.

## 변경

`native/windows-host`에 .NET 10/WinForms Windows x64 앱을 추가했다. 편집기와 수식 렌더러·폰트 경로를 빌드 시 EXE에 넣고 `https://localhost:49175`의 loopback HTTPS로 Word 작업창에 제공한다. Node/npm/Pages는 런타임에 사용하지 않는다. Office.js의 Microsoft CDN과 커뮤니티 네트워크 기능은 인터넷을 사용한다.

처음 연결 설정 버튼을 누르면 현재 사용자용 localhost TLS 인증서와 별도 Word 애드인 ID를 등록한다. 다른 애드인·기존 Pages/dev 등록과 조직 정책을 덮어쓰지 않는다. 인증서 키는 Windows 현재 사용자 키 저장소에, thumbprint/manifest는 앱 사용자 폴더에 보관한다. 연결 해제는 자체 등록·인증서만 제거한다. 포트는 설정 저장소의 출처를 유지하기 위해 고정하며 점유 시 오류로 중단한다. 창 닫기는 알림 영역, 앱 종료는 서버 종료다.

다운로드 코어를 이전 도우미와 공유한다. 번들 작업창은 전용 표지·정확한 로컬 출처·지정 헤더로 세션을 확인하고 메모리에서만 토큰을 사용한다. 별도 EXE·주소 복사 없이 자동 연결한다. 웹 작업창에서 임의 localhost 탐색을 하지 않으며 본문 네이티브 브리지도 자동 설치하지 않는다. API Origin/토큰·공식 목록·크기·시간·리디렉션 경계는 유지한다.

## 검증

- 단위 **573건**, 타입체크·Vite 빌드 통과. 일반 웹 작업창의 호스트 탐색 없음, 위조 표지의 다른 출처 거부, 지정 번들 출처의 세션 확인을 추가했다.
- Windows 앱·기존 도우미 개발 빌드 경고/오류 0개. Windows 앱 자체 포함 단일 EXE publish 성공. 프런트엔드 번들을 포함하며 별도 `dist` 디렉터리를 배포하지 않는다.
- 실제 Word `16.0.20527.20150`: `python scripts/windows-host/run.py`, `test-docs/windows-host/20261108-174745-4146ff/summary.json`.
  - 제품 `HostServer`와 실제 내장 번들을 별도 시험 호스트에서 실행. npm/Vite 서버 없음. 시험 제어 엔드포인트는 외부 Acceptance 프로젝트에만 있고 제품 EXE에는 없음.
  - 번들 UI 로드, Windows 세션 자동 연결, 실제 불러오기/적용 버튼, Word OMML 생성, 굵은 서식 왕복과 중복 구분자 없음 통과.
  - 토큰 없는 asset 요청 거부, 동일 출처 토큰으로 실제 GitHub 정식 릴리스 manifest 다운로드 통과.
  - 기존 신뢰된 Office 개발 인증서 사용. 고유 시험 애드인 등록·합성 문서만 사용하고 종료 후 등록/문서/시험 서버를 정리했다. 사용자 인증서 신뢰 저장소에 새 인증서를 추가하지 않았다.

중간 시험에서는 PEM의 Windows TLS 키 로딩 방식, Python의 cp949 기본 인코딩, 이전 시험 서버 종료 대기를 수정했다. 제품 인증서 생성/저장 방식은 처음부터 PKCS#12를 통한 Windows 사용자 키 저장소를 사용한다. 시험 인증서도 같은 종류의 로딩으로 맞춘 뒤 Word가 실제 작업창을 열었다. 최종 번들 서버 검사는 위 실행에서 통과했다.

## 아직 확인하지 않은 것 / 남은 작업

정상 제품 EXE의 첫 실행 인증서 신뢰 확인과 등록/해제 버튼 UI는 아직 사용자의 실제 저장소를 변경하며 검사하지 않았다. 통합 시험의 일시적 시험 등록/인증서와 구분한다. 따라서 첫 사용자 설정 흐름의 확인은 남아 있다. 서명된 설치 프로그램, 자동 업데이트/자동 시작, 기존 Pages 출처의 플러그인/옵션 이관도 후속이다. 현재는 EXE와 README를 담은 휴대용 ZIP이다.

본문 TSF/COM 실험을 제품 앱에 연결하지 않았고 `body` capability는 false다. 본문 자동 전환은 기존 5단계에 남긴다. Word 전용 개체 원본 보존 정책과 Word Undo/Redo 정책도 유지한다. Mac은 현재 구현 대상이 아니다.
