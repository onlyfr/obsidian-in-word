# 네이티브 run 서식 보존과 Word Undo (2026-11-07)

## 사용자 결정

실패 복구는 Word의 실행 취소/다시 실행에 의존한다. 별도 복구 UI, 자동 롤백이나 결과가 불확실한 변경의 재전송을 추가하지 않는다. 기존 실험용 current/original 복구 API는 과거 회귀 시험을 위해 남아 있지만 이번 사용자 흐름에는 연결하지 않는다.

## 구현

정상 소스 왕복에서 구체적인 글꼴 이름(ascii/hAnsi/eastAsia/cs 슬롯), 반 포인트 단위 크기(sz/szCs), RGB/자동 색상을 보존한다. 원본 문단의 텍스트 구간별 속성을 기존 문서 내 전환 기록에 담고, 렌더링할 때 Markdown의 굵게·기울임·취소선·코드 서식과 결합한다. Word가 등록 후 문단 표지에 글꼴/크기를 구체화하므로 그 타이포그래피도 함께 저장·적용한다. 코드는 기존대로 Consolas를 사용하며 코드 표지를 없애면 그 의미상 글꼴은 제거한다.

보이는 텍스트가 같으면 원본 위치별 서식을 그대로 붙인다. 한 원본 서식 구간 안의 연속적인 텍스트 교체는 해당 속성을 이어받고, 삽입 경계나 교체 구간에 다른 원본 서식이 섞이면 추정하지 않고 네이티브 쓰기 전에 멈춘다. 여러 곳을 한꺼번에 고치는 편집은 이 보수적인 단일 교체 판정에서 거부될 수 있다. 테마 오버라이드·강조색·문단 배치 등 아직 재현하지 못하는 속성은 거부한다. 등록할 때뿐 아니라 소스 전환 직전에도 지원 속성을 재검사한다.

네이티브 렌더러는 속성의 이름·길이·색상·크기 범위를 본문 변경 전에 검사한다. 실제 Font 속성 변경마다 기존 TSF/기한 가드를 적용한다. 임의 OOXML을 통째로 다시 삽입하지 않고 기존 문단 안에서 텍스트와 지원하는 속성을 적용한다. 전체 OOXML/모든 run 속성의 무손실 보존을 구현한 것은 아니다.

통신 예외와 결과 8/24는 명시적인 `NativeOutcomeUnknown`으로 구분한다. 세션을 멈추고 Word의 Ctrl+Z 안내를 표시하며 자동 전환을 재전송하지 않는다. 시험용 서버는 실제 작업자가 한 번 처리한 뒤 HTTP 응답 소켓을 끊어 응답 유실을 재현한다. 이는 인증된 개발용 테스트 경로에만 있다.

## 실제 Word 검증

Windows Word 16.0.20527.20112, 시험 소유의 acceptance.docx에서 스크립트로 확인했다. 키는 보내지 않았다. 사용자가 포커스를 유지할 수 있는 시간에 최종 세 묶음을 연속 실행했다.

| 시험 | 결과/증거 |
| --- | --- |
| 서식·응답 유실·Word Undo | `test-docs/word-host/20261107-000207-7df794/native-format-summary.json` 전체 통과 |
| 네이티브 선택·소유권 회귀 | `test-docs/word-host/20261107-000233-1b1509/native-selection-summary.json` 전체 통과 |
| 기존 네이티브 전환 회귀 | `test-docs/word-host/20261107-000309-70c615/native-flow-summary.json` 전체 통과 |

서식 fixture는 Cambria, 맑은 고딕, Arial의 문자 슬롯, 12.5/16pt, 복합 문자 크기 13pt, 빨강/파랑, 굵은 글씨를 섞었다. 변경 없는 두 번의 왕복과 redWord → redWorks 텍스트 편집 후 Word COM에서 원래 속성과 비교했다. 이웃 문단과 문단 수 2도 유지됐다.

렌더링은 성공했지만 응답을 잃은 경우, 새로운 런타임은 닫힌 기록을 읽기만 하고 렌더링을 다시 실행하지 않았다. Word Undo 2회로 편집한 Markdown 소스로 돌아갔고 같은 횟수의 Redo로 렌더링 상태와 원본 서식이 돌아왔다.

소스 진입 중 텍스트 교체 직후 실패를 주입한 경우에도 본문에 실제로 소스 문자열이 남았고, 세션은 정지했다. Word Undo 2회로 원래 텍스트·글꼴·크기·색상이 복원됐다. 소스 진입이 성공한 뒤 응답만 잃은 경우 역시 요청은 한 번만 제출했고, Undo 2회로 본문과 서식이 돌아왔다. 이번 새 시험에서는 별도의 current/original 복구 명령을 호출하지 않았다.

단위 테스트 492개, 타입체크/프로덕션 빌드, MSVC /W4 /WX 빌드 통과. 단위 검증은 Unicode 위치, 서식 경계의 모호함, 잘못된 속성 기록, 코드 글꼴 우선순위, 지원하지 않는 사후 서식 변경, 응답 유실 후 비재전송을 포함한다. 제품 메인 번들은 358.31 kB / gzip 116.81 kB로 유지됐다. 기존 native-flow의 단계별 복구 API 시험은 호환성 회귀이며 새 복구 정책의 사용자 인터페이스가 아니다.

## 확인된 제약

Word Undo는 본문을 되돌려도 콘텐츠 컨트롤의 source 태그를 남기는 경우가 있었다. 응답 유실 뒤 소스 진입을 Undo한 실측에서 텍스트는 서식 본문으로 돌아왔지만 태그는 source였다. 세션은 계속 정지해 있으며 태그를 자동으로 고치거나 자동 재개하지 않는다. Undo/Redo 기록을 보존하려고 상태 조회 중 메타데이터를 쓰지 않는다.

두 번은 이 시험 문서에서의 횟수다. 다른 문서/중단 지점에서는 여러 번 되돌려 문서를 확인해야 한다. 닫았다가 다시 열어 Undo 기록이 사라진 경우를 새 복구 흐름으로 해결하지 않는다. 삭제된 컨트롤 재생성이나 별도 복구 UI도 추가하지 않는다.

다음은 본문을 다시 쓰지 않는 안전한 상태 확인과 나머지 서식/IME 검증이다. 최종 독립 네이티브 앱과 npm/Pages 없는 실행 목표는 유지하며, 이번 변경을 제품 작업창 UI에 노출하지 않는다.
