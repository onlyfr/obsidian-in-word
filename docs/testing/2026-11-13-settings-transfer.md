# 웹 작업창 → Windows 앱의 플러그인·옵션 이관

2026-11-13. 기준 `708aba5`(Windows 설정 안정화 후). 저장소 출처가 다른 기존 작업창과 Windows 앱 사이를 명시적인 파일로 옮긴다.

## 사용과 범위

기존 작업창의 설정 → 커뮤니티 플러그인 → 플러그인·옵션 내보내기로 JSON을 만든 뒤 Windows 앱의 같은 위치에서 파일을 가져온다. 브라우저가 다운로드를 막으면 JSON 보기에서 복사해 UTF-8 파일로 저장할 수 있다. 파일에는 설치된 플러그인 코드/CSS/manifest/출처, 해당 플러그인 데이터, 에디터·수식 옵션만 담는다. 앱 자체 연결 정보·Word 문서·사이드카와 임의 저장소 키는 담지 않는다. 플러그인이 설정에 저장한 인증정보 등은 그대로 포함되므로 보관·공유에 주의한다.

파일은 최대 50MB, 플러그인 1,000개, 플러그인당 JS 20MB·CSS 2MB·manifest 64KB다. 버전/형식·중복 ID·옵션 값·실제 UTF-8 크기를 저장 전에 검증하며 UTF-8 BOM도 허용한다. 새 플러그인은 반드시 꺼짐으로 저장하고 코드를 실행하지 않는다. 같은 ID가 이미 설치돼 있으면 코드·켜짐 상태·플러그인 데이터를 모두 유지한다. 앱 옵션은 체크박스로 적용 여부를 정한다. 미리보기에서 개수와 정책을 확인하고 가져온다. 내보내기는 현재 화면의 옵션과 호스트의 loadData/saveData 설정을 사용하며, 플러그인이 별도로 직접 쓰는 다른 브라우저 저장소·보관함 파일은 포함하지 않는다.

가져오기와 내보내기 중에는 Word 적용 및 앱 옵션 변경을 막는다. 옵션을 적용해도 편집기 문서·Undo 기록을 초기화하지 않는다. Word 본문 쓰기/자동 전환은 하지 않는다.

## 저장과 중단 처리

- IndexedDB를 v2로 갱신하고 새 플러그인 전체와 완료 표지를 하나의 트랜잭션에 추가한다. `add()` 충돌·저장 실패는 전체를 거부한다. 기존 버전 창이 갱신을 막으면 빈 목록으로 보이지 않고 다른 창을 닫으라는 오류를 표시한다. 실제 영구 저장소가 없으면 가져오기를 거부한다.
- 설정과 플러그인 데이터는 기존 localStorage 구조를 유지한다. 쓰기 전 이전 값/가져올 값과 작업 ID를 중단 기록에 저장한다. 번들 저장 실패 또는 재시작 시 IDB 완료 표지를 확인하고 미완료 작업이 쓴 값만 되돌린다. 완료된 이관은 다시 실행하지 않는다. 이후 다른 창이 바꾼 값은 보존한다.
- Web Locks로 같은 출처의 이관을 직렬화하고 같은 작업창의 플러그인 작업과 Word 적용도 중복 실행하지 않는다. 일반 플러그인의 임의 저장까지 전역 잠그는 것은 아니므로 **다른 Word 작업창은 닫고 이관**한다. 두 저장소를 하나의 DB 트랜잭션으로 묶었다고 주장하지 않는다.
- 저장 결과를 확인하지 못하면 중단 기록을 유지하고 새 이관을 덮어쓰지 않는다. 다시 열 때 플러그인을 불러오기 전에 기록을 확인한다. 이는 앱 설정 처리이며 Word 본문 자동 복구 기능이 아니다.
- 다른 창이 마지막 플러그인을 삭제했을 때 메모리 캐시를 대신 반환해 되살리던 목록 처리도 수정했다.

## 검증

- JS 단위 **596개**·타입체크·빌드 통과. 새 archive/service/UI 테스트와 Word 작업 중 이관 거부 포함. IndexedDB 트랜잭션은 개발 전용 `fake-indexeddb`로 검사하며 런타임 번들에는 넣지 않는다.
- 검증: 형식/중복/크기·비정상 숫자/BOM, 꺼짐 저장·미실행, 기존 코드/설정 보존, 옵션 제외, 실제 IDB 모형의 충돌 전체 abort, 설정 쓰기/DB 실패, 완료 신호 손실·완료 후 기록 삭제 실패, 미완료/완료 중단 기록·이후 편집 보존, 알 수 없는 저장 결과, 잘못된 기록의 임의 키 변경 거부, 잠금/영구 저장 불가, v1 갱신 막힘, 캐시 되살림 방지, 취소/큰 파일 사전 거부/다운로드 차단 시 JSON 표시.
- 실제 Word `16.0.20527.20150` 웹 출처: `test-docs/word-host/20261113-123856-d5263d/transfer-summary.json`. 기존 설정 UI 회귀 후 제품 Export 버튼이 만든 Blob과 수동 복사 JSON을 비교했다. 합성 플러그인 2개·데이터·옵션을 포함하고 시험용 연결/문서 저장 키는 제외했다. OS 다운로드 완료까지 시험한 것은 아니며 생성된 JSON을 시험 러너가 파일로 기록했다.
- 실제 번들 Windows 앱 출처: `test-docs/windows-host/20261113-124005-8d290f/transfer-summary.json`. 출처는 `https://localhost:13001` → `https://localhost:49175`로 다르다. 실제 GitHub Pages 계정 데이터는 읽지 않고 같은 제품 웹 UI의 합성 자료를 사용했다.
- 앱에서는 취소·새 플러그인 꺼짐·기존 활성 9.0.0/데이터 유지·옵션 미적용/적용·실제 컨트롤/편집기 크기 갱신·반복 이관 건너뛰기·잘못된 버전 거부·수동 활성화를 검사했다. Word/편집기 텍스트는 동일했다. 미완료 설정 기록을 심고 Word를 실제 저장·닫기·다시 열어 설정 처리와 플러그인/데이터/옵션 보존을 확인했다. 시험 플러그인을 삭제하고 이전 앱 옵션을 복원했다.
- 같은 앱 실행의 기존 번들 UI·불러오기/적용·OMML·굵은 서식·다운로드 인증/실시간 GitHub 회귀도 통과했다. 현재 UI 옵션 스냅샷·JSON 복사 경로·일반 Word 작업 중 초기화 보강 후 위 이관 실행을 최종 재검증했다.

원본 웹 저장소는 지우지 않는다. 기존 ID 덮어쓰기, 자동 활성화, 암호화된 백업, Word 문서/사이드카 내보내기는 제공하지 않는다. 실제 사용자 인증서 신뢰 창, 서명/업데이트, 본문 네이티브 연결과 자동 전환의 남은 계획은 그대로 유지한다.
