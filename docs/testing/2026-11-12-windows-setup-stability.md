# Windows 첫 설정·해제와 종료 안정성

2026-11-12. 기준 `eba302e`(PR #44 후 문서 반영). 4단계 Windows 앱의 첫 설정 준비를 보강했다.

## 수정

기존 설정 경로는 인증서를 갱신하기 전에 이전 등록과 인증서를 제거했다. 이후 신뢰 취소나 파일/레지스트리 쓰기 실패가 나면 기존 연결 정보를 잃을 수 있었다. 새 개인 인증서·신뢰 확인·manifest/인증서 참조·등록을 먼저 완료하고, 완료 후 이전 인증서를 정리하도록 바꿨다. 실패 시 해당 작업이 쓴 등록·파일을 이전 값으로 되돌리고 생성한 인증서를 정리한다. 다른 등록이 감지되면 덮어쓰지 않는다.

인증서 변경 전에 `certificate-pending` 소유권 기록을 저장한다. 정리 실패 시 기록을 유지해 다음 설정/해제에서 재확인한다. 등록 직후 앱이 중단된 경우 활성 인증서를 잘못 삭제하지 않는다. 기존 PR #44 인증서는 이름/주체로 호환 확인하고, 새 인증서는 조직 주체를 포함한다. 앱 소유로 확인되지 않은 인증서는 삭제를 거부한다. 등록 XML은 선언/공백 차이 때문에 다시 등록하게 하지 않으며 잘못된 XML은 유효 등록으로 처리하지 않는다. 파일은 같은 디렉터리의 임시 파일을 완성한 뒤 교체한다.

시작·설정·해제를 하나의 실행 경계로 묶어 겹친 요청을 받지 않는다. 종료 요청은 새 작업을 막고 진행 중 작업이 끝난 뒤 서버·인증서를 한 번 정리한다. 반복 종료 요청은 같은 종료 작업을 기다린다. 정리 도중 오류가 나도 서버 dispose와 인증서 해제를 시도한다. Word 본문과 Undo/Redo 정책은 바꾸지 않는다.

## 검증

- JavaScript 단위 **573개**, 타입체크·Vite 빌드 통과. 웹 번들 기능 변경 없음.
- Windows 격리 회귀 **29개**: `dotnet run --project scripts/windows-setup-checks/WindowsHostChecks.csproj -c Release`. 증거 `test-docs/windows-setup/20261112/summary.json`.
  - 설치/반복/해제, 단계별 쓰기 전·후 실패, 예외 없이 신뢰가 거부된 경우, 갱신 실패 시 이전 등록/인증서/파일 유지, 성공한 갱신의 이전 인증서 정리.
  - 외부 등록 보존, 정리 실패 후 재시도, 등록 완료 직후 중단 상황, 다른 인증서 삭제 거부, PR #44 인증서 및 manifest 호환.
  - 실제 제품 생성기의 localhost SAN·TLS 서버 EKU·비-CA·개인 키 프로필. 시험은 비영구 개인 키와 메모리 저장소를 사용한다.
  - 중복 작업 거부, 진행 중 종료 대기·한 번만 stop, 종료 뒤 새 작업 거부, 작업 실패 뒤 게이트 해제.
- 사용자 Windows 인증서 신뢰 저장소와 제품 애드인 등록은 격리 회귀에서 수정하지 않았다. fake 저장소는 단계별 실패를 주입하며 제품 설치/종료 코어를 그대로 호출한다. fake 성공을 실제 Windows 신뢰 창 통과로 해석하지 않는다.
- 실제 Word `16.0.20527.20150` 번들 호스트 회귀 통과: `test-docs/windows-host/20261112-171703-8c14a1/summary.json`. 내장 UI·자동 세션·실제 불러오기/적용·OMML/굵은 서식 왕복·인증 없는 다운로드 거부·실시간 GitHub 다운로드 확인. 기존 신뢰된 개발 인증서와 별도 임시 시험 등록을 사용하고 정리했다.
- 자체 포함 Windows x64 publish와 GitHub Windows 빌드에 격리 회귀를 포함한다.

실제 Windows 신뢰 확인 창·첫 설정/해제 버튼 UI의 사용자 환경 시험은 아직 남아 있다. 서명된 설치 프로그램·업데이트·자동 실행, Pages 플러그인/옵션 이관, 본문 TSF/COM 제품 연결도 별도 후속이다. 본문 자동 전환은 5단계의 마지막 순서로 유지한다.
