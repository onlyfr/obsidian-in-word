## 결과와 사용

설정 → 커뮤니티 플러그인에서 공식 목록을 불러오고 검색한다. 이름·설명·제작자·저장소를 모두 검색하며 20개씩 표시한다. 저장소 링크·설치 버전을 함께 표시하고 새로고침 실패 시 기존 목록을 유지한다.

GitHub 릴리스 첨부파일은 실제 Word WebView에서 CORS로 직접 받지 못했다. 임의 외부 프록시를 추가하지 않고 전용 Windows 다운로드 도우미를 만들었다. ZIP을 받아 EXE를 실행하고, 도우미 창의 연결 주소를 작업창에 붙여넣어 연결한다. 공식 목록 검색에는 도우미가 필요 없다. 배포 EXE는 자체 포함이며 npm/.NET 런타임 설치가 필요 없다. 전체 앱 네이티브 전환을 완료한 것은 아니다.

다운로드는 최신 정식 릴리스의 manifest/main/선택 CSS만 사용한다. manifest ID가 선택한 목록의 ID와 일치해야 한다. JS 20MB·CSS 2MB·manifest 64KB, 스트림 바이트·시간을 제한한다. 원격 목록/manifest 문구는 HTML로 해석하지 않는다. 다운로드만으로 코드를 실행하지 않고 꺼짐으로 설치한다. 기존 켜기/끄기·명령·설정·삭제와 연결하며, 호환성 오류/미지원 API를 표시한다. 공식 목록 등재와 이 호스트의 호환성은 별개다.

기존 설치 교체는 파일을 받은 후 기존/새 버전을 확인한다. 실패·취소 시 설치를 건드리지 않으며 성공 후에도 꺼짐이다. 플러그인 데이터는 유지한다. 설치·교체·켜기/끄기·삭제·파일 가져오기 작업을 중복 실행하지 않고, 확인 중 설정 창을 닫으면 취소한다. IndexedDB 요청 성공만으로 저장을 확정하지 않고 트랜잭션 완료를 기다린다. 저장 실패는 오류로 처리하고 메모리 전용 저장은 안내한다.

도우미는 무작위 loopback 포트·256비트 세션 토큰·허용 Origin을 사용하며 공개 서비스로 듣지 않는다. 공식 목록의 ID/저장소와 GitHub asset ID만 받고 임의 URL·파일 경로·명령을 받지 않는다. HTTPS 리디렉션은 GitHub의 두 첨부파일 호스트로 제한한다. 작업창은 명시적인 연결 주소만 사용하며 자동 localhost 탐색·토큰 영구 저장을 하지 않는다. [상세 경계/빌드 안내](../../native/plugin-downloader/README.md).

## 제약과 미확인

배포 단일 EXE를 로컬에서 직접 실행하는 추가 검사는 자동 승인 검토에 두 번 차단됐고 상세 이유는 제공되지 않았다. 강제 종료 대신 스스로 종료하는 headless 시험 모드도 준비했으나 해당 실행 역시 차단됐다. 따라서 배포 EXE는 **빌드 확인**, 개발 빌드는 **실제 Word 통합 확인**으로 구분한다. headless 모드는 최장 10분 뒤 종료하며 일반 도우미 창의 수명과는 다르다.

중간 재열기 시험 두 번은 시험 코드의 `must` 선언 누락/선언 위치 문제로 실패했다. 제품 저장소를 초기화하거나 조건을 완화하지 않고 시험 코드를 고친 뒤 위 최종 재열기 검사가 통과했다. 이후 추가한 CSS 중복 검사와 headless 자동 종료는 빌드로 확인했고 해당 커뮤니티 통합 시험은 다시 실행하지 않았다.

현재 도우미 배포는 Windows x64다. 서명/설치 프로그램·Mac/웹 Word·모든 커뮤니티 플러그인 호환성을 검증한 것은 아니다. GitHub 비인증 API 한도와 네트워크 실패는 안내 후 사용자가 다시 시도하며 자동 반복 설치/업데이트를 하지 않는다. 문서 글꼴 선택은 기존 후속 항목, 본문 자동 전환은 마지막 순서를 유지한다.
