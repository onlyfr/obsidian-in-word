# 네이티브 본문 전환 통합 (2026-11-06)

## 구현 범위

`BodyEditSession`에 선택적인 `commit` 경로를 추가했다. `NativeBodyPort`는 주입된 `NativeBodyHost`로 문단과 복구 기록을 읽고, 소스/렌더링 전환에 필요한 스냅샷·커서 매핑·마크다운에서 만든 run·복구 기록을 하나의 네이티브 요청으로 보낸다. 이 포트와 변환·세션 모듈은 Office.js/HTTP에 의존하지 않는다. 기존 `WordBodyPort`의 Office.js 경로는 유지했다.

네이티브 호스트는 Word UI 스레드에서 문서 경로, 컨트롤 ID/태그, 원문/OOXML, 선택 범위, 조합 상태와 요청 기한을 검사한다. 복구 기록을 먼저 남긴 뒤 텍스트, run 서식, 모드와 선택을 갱신하고 기록을 완료한다. 내용이 바뀐 중간 단계와 태그까지 바뀐 단계를 구분하며, 불확실한 `prepared/content` 상태의 현재 내용을 임의로 마크다운으로 해석하지 않는다.

기존 XML part는 삭제하지 않고 `DocumentElement.Text`를 바꿔 ID를 유지한다. 이미 내용이 있는 part에 `LoadXML`을 다시 호출하는 방식은 실제 Word에서 실패했다. 렌더링은 기존 문단 경계를 유지하며 텍스트와 굵게/기울임/취소선/코드 run을 네이티브로 적용한다. `InsertXML`로 문단 전체를 가져오는 방식은 이 경로에서 빈 문단을 추가해 사용하지 않는다.

Word COM 호출이 메시지를 처리하는 동안 관찰기를 해제하지 않도록 실행 중 쓰기와 TSF 콜백을 추적한다. 관찰기를 다시 붙일 때는 새 epoch를 발급하며, 이전 관찰기의 스냅샷으로 변경할 수 없게 한다. 완전한 TSF 트랜잭션 잠금을 구현한 것은 아니다. 각 변경 전 실제 조합을 확인하고, 중단 시 문서 내 기록으로 복구한다.

## 개발 시험 경로

`npm run test:word -- --native-flow-only`는 키를 전송하지 않지만 실제 Word 문서 포커스가 필요하다. 테스트 서버의 네이티브 RPC는 이 모드에서만 켜고 실행별 토큰과 로컬 Origin을 검사한다. 허용 연산은 read/journals/transition뿐이며, 호출자가 스크립트나 파일 경로를 제출할 수 없다. COM 작업자는 자체 `acceptance.docx`만 다룬다. 제품 작업창에는 이 서버/포트를 연결하지 않는다.

일반 본문 문단 하나와 텍스트·강조·취소선·인라인 코드가 대상이다. 목록·수식·링크·객체·필드·변경 추적 및 일부 표현하지 못하는 run 서식은 거부한다. 전체 글꼴/색/크기 서식 보존, 여러 문단 편집, 공동 편집과 임의 문서에서의 동작은 아직 검증 범위가 아니다.

## 확인한 결과

- 단위 테스트 **477개**, 타입체크/빌드, MSVC `/W4 /WX` 빌드 통과. 네이티브 commit 사용, 커서/선택 매핑, 원문 불일치, 지원하지 않는 문법, 중단 복구, 요청 비재시도, 리터럴 `<br>`, 제어 문자 처리 등을 포함한다.
- 실제 핵심 통합 시험: `test-docs/word-host/20261106-222411-d4aff7/native-flow-summary.json`. 소스 진입, COM 소스 편집, 굵게/기울임/취소선 복원, 외부 커서 상대 위치 4와 문단/이웃 보존, 3회 반복 전환을 통과했다. 첫 진입/이탈은 `Word.run`을 예외를 던지는 함수로 바꾸고 실행해 Office.js 우회 여부도 검사했다.
- 같은 실행에서 기록 준비/내용 교체/태그 교체 뒤의 세 중단 지점 복구, 실제 저장·닫기·재열기 후 새 작업창/관찰기로 현재 소스 복구를 통과했다.
- 실행 취소는 **2회**에 소스 텍스트와 source 태그로 돌아왔다. 첫 회는 메타데이터, 다음 회는 내용/모드가 바뀌었다. 복구 기록을 읽은 뒤에도 다시 실행이 유지됐다. 사용자에게 한 번에 되돌아간다고 안내하지 않는다.
- 기존 전체 Word 회귀: `test-docs/word-host/20261106-222855-7ea5e8/report.md` 통과. 기존 보존·서식 왕복·수식·대형 문서·본문 세션 시험을 포함한다.

최종 통합 재실행도 통과했다: `test-docs/word-host/20261106-224631-6dbe90/native-flow-summary.json`. 위 핵심 흐름에 더해 닫기 중 내용 교체 뒤 실패의 원본 복구, 재연결 후 이전 epoch 거부, 컨트롤 ID 유지, 한글·이모지·코드 서식과 UTF-16 커서 상대 위치 8, 마지막 이웃/문단 보존을 확인했다. 재열기 후 시험용 검사 함수 초기화가 빠져 처음 멈춘 것은 도구에서 수정하고 다시 실행했다.

기존 가드 재검사 `test-docs/word-host/20261106-224719-5948c0/guard-summary.json`도 통과했다. 실제 가상 키 입력 재검사 `test-docs/word-host/20261106-224736-1a47de/input-summary.json`에서는 `NativeGuardBlockedActive=true`, 자동 IME 연결, 조합 중/불명 상태의 선택 조회 0회, 외부 커서 4 유지와 단절 게이트를 확인했다. 변경된 관찰기 epoch와 메모리 프로토콜이 기존 경로에서도 동작했다. 시험 Word와 네이티브 관찰기는 모두 종료했다.

제품 메인 번들은 358.31 kB / gzip 116.81 kB, Word 청크는 170.11 kB / gzip 68.12 kB다. 네이티브 포트는 제품 번들에 포함하지 않는다. 표용 `inlineToRuns`를 재사용하되 일반 문단에서는 리터럴 `<br>`를 줄바꿈으로 해석하지 않도록 옵션을 분리했다.
