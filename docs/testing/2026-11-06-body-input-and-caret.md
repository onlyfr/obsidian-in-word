# 본문 입력·커서 검증 (2026-11-06)

## 결과와 범위

Windows 데스크톱 Word 16.0.20527.20112에서 일반 문단의 소스 진입 커서와 선택 범위를 보존했다. 실제 가상 키 입력으로 한글을 입력하고 Space로 확정한 뒤 문단을 렌더링했다. 제품 작업창에는 연결하지 않은 개발용 실험이다.

**실제 IME 조합 시작/종료의 자동 감지는 미완료다.** 외부 프로세스에서 Word 포커스 HWND의 IMM32 컨텍스트를 얻지 못했다. 한글 입력은 성공했지만 `ActualCompositionVerified=false`다. 이는 해당 관찰 방법의 한계이며 Word의 한글 입력 지원 여부를 뜻하지 않는다. 테스트는 Space 입력 후 명시적으로 idle 신호를 보냈다. 시간 경과나 선택 이벤트를 IME 종료 신호로 사용하지 않는다.

## 변경

- `caret-map.ts`: Lezer 구문 트리로 보이는 텍스트의 UTF-16 위치를 마크다운 위치로 변환한다. 강조·링크·인라인 코드·이스케이프·엔티티를 처리한다. 원문과 화면 텍스트가 다르면 위치를 추측하지 않고 거부한다.
- `WordBodyPort.source`: WordApiDesktop 1.4 지원을 확인하고 선택 양 끝을 읽어 소스 전환 후 복원한다. 이 API가 없는 호스트는 실험을 거부한다. 다른 문단으로 이동한 경우도 덮어쓰지 않는다.
- `BodySelectionDriver`: 기본 입력 상태는 unknown이며 게이트를 닫는다. unknown/active 중 선택 이벤트는 Word를 조회하거나 문단을 전환하지 않는다. idle은 최신 선택을 읽은 뒤 해제하며 오래된 비동기 조회는 무시한다. 조회 오류·종료에서는 세션을 멈춘다. 신뢰할 수 있는 네이티브 조합 신호 공급은 다음 작업이다.
- 좁은 실험용 HTML 코덱에서 언어·글꼴 span을 평탄화하고 인접한 동등 강조를 합친다. 한글을 입력한 Word가 굵은 run을 나누어 `**bo****한글**`처럼 구분자가 이어지던 문제를 방지한다. 임의의 Word run 서식 보존을 구현한 것은 아니다.
- 별도 foreground 키보드 시험을 추가했다. 자체 문서만 열고 각 키 전에 자체 Word PID와 루트 창을 확인한다. 다른 창으로 포커스가 옮겨지면 입력을 중단한다. 기존 키보드 레이아웃만 사용한다.
