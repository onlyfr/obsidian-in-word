# 본문 세션 상태·복구 기반 — 2026-11-06

## 범위

네이티브 앱이라는 최종 목표에 맞춰 상태 전환 코드를 호스트와 분리했다. `src/body/session.ts`는 Word/Office/브라우저 전역에 의존하지 않는 상태 관리자이며, Word용 포트와 일반 문단용 변환 코덱은 별도 모듈이다. 현재 제품 작업창에는 가져오지 않으므로 프로덕션 번들·사용 흐름은 그대로다.

이번 단계는 일반 문단의 개발용 실험이다. 네이티브 앱 기술 선택, 설치 패키지, 원본/실시간 미리보기 전체 UI는 아직 구현하지 않는다. 현재 npm/Pages 환경은 검증 도구다.

## 상태와 보존 정책

- 문자열 내용이 아닌 고유 블록 키로 콘텐츠 컨트롤을 찾는다. 같은 글자의 다른 문단을 대신 편집하지 않는다. 키가 중복되거나 컨트롤이 없어지면 멈춘다.
- 문단의 OOXML 본문을 리비전 토큰으로 비교하고, 관측 뒤 다른 작업이 바꿨으면 덮어쓰지 않는다. Word가 매번 바꾸는 문단/리비전 ID는 기존 정규화로 제거한다.
- 문서의 별도 Custom XML 네임스페이스에 원래 마크다운·문단 스타일·원래 리비전과 `opening / editing / closing / closed` 체크포인트를 남긴다. 이는 Word 변경과 원자적 트랜잭션이 아니다. 부분 실패는 재시도하지 않고 모호한 상태를 명시적 복구 대상으로 남긴다.
- 소스→렌더링은 현재 편집 내용을 사용한다. 명시적인 원본 복구는 진입 전 마크다운과 문단 스타일을 사용한다. 모든 Word 서식의 OOXML 무손실 복구를 뜻하지 않는다. 객체·수식·필드·변경 추적·목록·표·여러 문단은 이 실험에서 거부한다.
- 빠른 선택 요청은 직렬화하고 대기 중 마지막 요청을 처리한다. 소스 진입 직전 실제 커서가 해당 블록에 있는지도 확인한다. 문단 경계의 `ContainsStart/ContainsEnd`도 포함 여부에 맞게 취급한다.
- 조합 중에는 새 전환을 대기시키는 호스트 신호 인터페이스를 뒀다. **실제 IME 신호는 연결하지 않았다.** 이미 호스트에 제출된 배치를 취소하는 기능도 아니다.
- 실행 취소 등으로 관측한 모드가 달라지면 자동 편집을 멈춘다. 관측만으로 저널/본문을 다시 쓰지 않아 Word의 다시 실행 기록을 보존한다. 중단 후 현재 소스를 렌더링하거나 원본을 복원하는 동작은 명시적으로 호출해야 한다.
- 삭제한 컨트롤을 자동 생성하지 않으며, 남은 복구 기록도 자동 삭제하지 않는다.

## 검증

단위 시험은 빠른 이동, 조합 대기, 리비전 충돌, 삭제, 실행 취소로 상태 변경, 새로운 컨트롤러에서의 복구, 지원하지 않는 소스와 렌더링 실패, 태그 기록 전 부분 실패를 다룬다.

실제 Windows Word `16.0.20527.20112`에서 `npm run test:word -- --body-session-only`로 다음을 확인했다.

| 항목 | 결과 |
| --- | --- |
| 같은 텍스트를 가진 두 블록 | 키별로 구분해 한쪽 편집을 다른 문단에 적용하지 않음 |
| 빠른 A→B→A 요청 | 마지막 A만 소스 상태로 남음 |
| 조합 대기 게이트 | 대기 중에는 블록을 바꾸지 않고 해제 뒤 마지막 요청 처리; 실제 IME 시험은 아님 |
| 한글 소스 | `한글 **보존**`을 새 컨트롤러에서 복구해 `한글 보존`과 굵게 유지 |
| 본문 쓰기 직후 연결 실패 주입 | 실제 Word 텍스트 쓰기는 1회, 모호한 현재 내용 자동 해석 거부, 명시적 원본 복구 성공 |
| 실제 문서 저장·닫기·재열기 | 이전 작업창 JS 상태 없이 문서 안의 저널로 소스를 찾고 편집 내용을 복구 |
| 네이티브 실행 취소/다시 실행 | 렌더링을 되돌리면 태그/텍스트가 소스 모드로 돌아옴. 관측 중 덮어쓰지 않고 정지하며, 다시 실행 가능 |
| 소스로 되돌린 뒤 복구 | 문서 저널과 현재 소스로 렌더링 복원 |
| 컨트롤 삭제 | 삭제된 블록을 재생성하지 않고 이웃 문단 보존, 저널은 확인용으로 유지 |

해당 Word 빌드에서는 렌더링 배치의 실행 취소가 1단계였고 Custom XML 체크포인트는 그대로 남아 있었다. 따라서 저널만으로 현재 모드를 판단하지 않고 실제 컨트롤 모드·리비전도 함께 확인한다. 다른 Word/네이티브 호스트에도 같은 실행 취소 특성이 있다고 가정하지 않는다.

`npm test` **410개**, `npm run build`(타입체크 포함), 전체 `npm run test:word`와 자동 정리까지 통과했다. 제품 엔트리에서 이 모듈을 가져오지 않아 메인 번들은 기존 **358.31 kB / gzip 116.81 kB**, 프로덕션 빌드 산출물도 이전과 동일하다.

최종 전체 실행 증거는 gitignore 대상 `test-docs/word-host/20261106-200044-447c54`의 `results.jsonl`, `com-results.jsonl`, `summary.json`, `report.md`다. 집중 실행은 `20261106-195531-c2140b`에서도 통과했다. 중간 전체 실행에서 Word 기동 중 COM의 일시적인 호출 거절이 발생해, 시험 도구의 읽기/기동 작업에만 제한적 재시도와 헬퍼 조기 종료 감지를 추가했다. 문서 수정·실행 취소·실패한 변환은 재시도하지 않는다.

## 다음 검증

실제 한글 IME/키 입력 이벤트, 빠른 이동 중 커서 위치, 문서 보호·공동 편집·원격 변경, 복합 객체/서식, 모드 태그와 본문이 부분적으로만 바뀐 모든 실패 위치를 더 검증한다. 공식 [콘텐츠 컨트롤 API](https://learn.microsoft.com/javascript/api/word/word.contentcontrol?view=word-js-preview)의 태그/범위 동작을 사용하지만, 네이티브 앱은 동일한 세션 포트를 별도 호스트로 구현할 수 있다.

이 문서가 전체 실시간 편집 기능의 완성을 의미하지 않는다. 제품 UI에는 아직 연결하지 않았다.
