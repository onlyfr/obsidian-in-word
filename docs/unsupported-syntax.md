# 지원하지 않는 문법의 처리 방침 (설계 결정)

마크다운 쪽 문법 중 Word에 대응하는 객체가 없는 것(Mermaid, Temml이 그리지 못하는 수식, 코드 블록 렌더러 계열 등)을 어떻게 보여 주고 어떻게 되돌릴지에 대한 결정이다. 원칙은 **내용을 절대 잃지 않는 것**, 그 다음이 **정확한 왕복**이고 보기 좋은 렌더링은 그 뒤다.

## 3단계 사다리 (위에서부터 가능한 것을 쓴다)
1. **Word 네이티브 객체**: Word에서도 편집할 수 있는 객체가 있으면 그것을 쓴다. (예: 수식은 OMML. 이미 구현됨.)
2. **이미지 렌더링 + 소스 보존**: 네이티브 객체는 없지만 안전하게 그릴 수 있으면 그림으로 넣는다.
   - 원본 소스는 사이드카(Custom XML Part)에 id(소스의 안정 해시)로 저장한다. 수식의 LaTeX↔OMML 쌍과 같은 방식이다.
   - 이미지의 대체 텍스트에 `owb:<id>` 표지와 사람이 읽을 수 있는 요약을 넣는다. 불러올 때 이 표지로 짝을 찾는다.
   - **불러오기**: 에디터에는 이미지가 아니라 **원본 소스**(예: ` ```mermaid` 블록)가 나타난다. 그래서 계속 마크다운으로 편집한다.
   - **적용**: 소스가 바뀌지 않았으면 저장된 이미지를 그대로 복원(바이트 동일), 바뀌었으면 다시 그려서 교체한다.
   - Word에서 사용자가 이미지를 지우면 자리표시자와 마찬가지로 적용 시 객체가 사라진다(안전장치: 개수 불일치는 적용 거부, 수식·떠 있는 개체와 동일한 방식).
3. **소스 그대로 표시**: 그릴 수도 없으면(렌더러 로딩 실패, 오류, 크기 초과) 소스를 코드 스타일 문단으로 두고 눈에 띄는 경고를 붙인다. 어떤 경우에도 내용은 남는다.

## 결정 사항
- **형식**: 기본은 **PNG(2배 해상도)**. SVG는 Word 버전별 지원 차이가 있으므로 실제 Word에서 확인되기 전에는 기본값으로 쓰지 않는다. (확인되면 SVG를 선택지로 추가.)
- **대체 텍스트**: 접근성을 위해 소스의 요약(첫 줄과 종류)을 넣는다. 전체 소스는 사이드카에만 둔다.
- **대상 문법 (우선순위)**
  1. **수식 중 OMML로 변환할 수 없는 것**: 가장 먼저 한다. 사다리는 OMML(편집 가능한 Word 수식) → **LaTeX를 렌더링한 이미지** → LaTeX 원문 순이다. 이미지로 들어간 수식도 불러오면 **`$…$` LaTeX가 에디터에 나타나 계속 편집**할 수 있다(사이드카에 LaTeX 원문 + 이미지 쌍 저장, 대체 텍스트의 `owb:<id>` 표지로 짝을 찾는다). 편집하면 다시 OMML로 시도하고, 안 되면 이미지를 다시 그린다.
  2. **Mermaid** 등 코드 블록 렌더러. 같은 인터페이스(`종류 → 렌더러`)로 하나씩 추가한다.
- **렌더러는 지연 로딩**: 메인 번들에 넣지 않는다. 로딩 실패 시 3단계로 대체하고 알린다.
- **보안**: 렌더러는 엄격 모드(스크립트·외부 요청·`javascript:` 링크 금지)로 실행하고, 출력은 정제한 뒤에만 그림으로 만든다. 네트워크에서 리소스를 가져오지 않는다.
- **크기 제한**: 이미지 크기·소스 길이에 상한을 두고, 넘으면 3단계로 대체한다. 사이드카는 사용하는 항목만 남긴다.
- **설정 탭의 미지원 컨트롤**은 이미지가 아니라 건너뛰기 + 호환성 보고서 기록으로 처리한다(설정은 눈으로 보는 용도가 아니므로).

## 수식 이미지의 추가 고려사항 (구현 시 확인할 것)
- **래스터화 방식**: (a) Temml MathML을 SVG `foreignObject`에 넣어 캔버스로 그리는 방법(캔버스 오염 여부를 WebView2에서 확인), (b) 순수 SVG를 만드는 렌더러를 지연 로딩하는 방법 중 더 견고한 쪽을 실측으로 고른다.
- **인라인 수식의 기준선**: 이미지가 글자 기준선에 맞게 보이도록 렌더링 지표로 세로 위치를 보정한다(`w:position` 등). 독립(display) 수식은 가운데 정렬 문단으로 넣는다.
- **다크/라이트 무관**하게 읽히도록 배경 투명 + 글자색 자동(문서 글자색 사용) 여부를 정한다.
- 대체 텍스트에는 LaTeX 원문(길면 잘라서)을 넣어 접근성을 확보한다.

## 수식 이미지: 구현 상태 (`math-image` 브랜치)
**구현됨 (코드 + 단위 테스트)**: 사다리 OMML → PNG 그림 → `$…$` 소스 글자, 사이드카 `kind=mathimg`, 대체 텍스트 `owb:math:<id>[:d] <LaTeX>`, 불러오기/적용/정리, 한도·시간 제한, 지연 로딩(메인 번들 +1.3 kB). 자세한 사용법은 README '수식' 참고.

**래스터화 방식 측정** (같은 수식 12개, 3배 해상도, Chromium 156 = WebView2와 같은 엔진, Windows 11; *실제 Word WebView2에서의 재측정은 아직 못 했음*):

| | (a) Temml MathML → SVG `foreignObject` → canvas | (b) MathJax 3 SVG 출력 → canvas |
|---|---|---|
| 추가 코드 | 이미 있는 Temml(지연 청크 204 kB, gzip 60 kB) + 래스터라이저 2.8 kB | `tex-svg.js` 2.1 MB (gzip 680 kB), Apache-2.0 |
| 로딩 | Temml+CSS+모듈 약 110 ms | 약 90–130 ms |
| 수식당 시간 | 4–41 ms (첫 수식이 가장 느림) | 4–52 ms |
| 캔버스 오염 | 없음 (data: URI SVG, `getImageData`/`toDataURL` 성공) | 없음 |
| 투명 배경 | 예 (모서리 알파 0) | 예 |
| `\cancel`, `\color`, `\boxed`, `\tag` | 모두 그려짐 | `\cancel`/`\color`는 확장 모듈을 네트워크(`//../../es5/input/tex/extensions/*.js`)에서 가져오려다 실패 (네트워크 금지 원칙 위반) |
| 글꼴 | 시스템의 Cambria Math (Temml 기본 CSS) | 자체 경로 글꼴 |
| PNG 크기(예: `\cfrac` 4단) | 8.8 kB | 7.8 kB |

(a)를 채택: 새 의존성이 없고, 미리보기와 같은 정제된 Temml 파이프라인(스크립트·외부 요청 없음)을 쓰고, 네트워크 없이 모든 시험 수식이 그려집니다. (a)의 주의점: 글꼴이 **그리는 PC의 수학 글꼴**에 의존합니다(Windows는 Cambria Math). Mac/웹 Word에서 그리면 글꼴이 달라질 수 있지만 PNG는 만든 시점에 고정되므로 이후에는 안정적입니다.

**텍스트 색 정책**: 검정(#000) 고정 + 투명 배경. 어두운 배경 문서에서는 글자가 안 보일 수 있습니다(추후 문서 글자색을 읽어 반영 가능). 글자 크기는 본문 11pt 기준이며 id에 포함하지 않습니다(다른 크기의 본문이면 상대적으로 작거나 크게 보임).

**OMML 변환 불가 + Temml 가능 수식 (시험 말뭉치, `tests/mathimg.test.ts`)**: `\xrightarrow`, `\boxed`, `\cancel`/`\bcancel`, `\color`/`\textcolor`, `\operatorname*`, `\mathcal`/`\mathfrak`, `\widehat`/`\widetilde`, `\overrightarrow`, `\not`, `\stackrel`, `\substack`, `\cfrac`, `\pmod`, `\phantom`, `\fbox`/`\colorbox`, `\sideset`, `\tag`. 변환되는 것(1단계): `\underbrace`/`\overbrace`, `cases`, `aligned`, `\overset`, `\binom`, `\operatorname`. Temml도 못 그리는 것: 알 수 없는 명령, 없는 환경(`tikzpicture`, `eqnarray`), `\href`(trust 없음), `\enclose`.

**아직 안 된 것 / 실제 Word에서 확인 필요**: Word 삽입(`w:position` 기준선, 그림 크기), Word가 다시 저장할 때 `descr` 유지, 실행 취소 한 번, 다음 불러오기 멈춤 없음, 표·목록·떠 있는 그림·추적 변경과 한 선택 영역에서 공존, 저장 후 다시 열기, 100% 확대 선명도. 표 안의 수식 그림은 풀지 못하고 적용이 중단됩니다(표 안 Word 수식과 같은 한계). 본문 글자 크기/색 반영, SVG 형식은 없음. Mermaid 등 다른 렌더러(렌더러 인터페이스 일반화)는 다음 단계.

## 구현 순서
표 변환(완료, README '표' 참고) → 수식 이미지(OMML 불가 수식) → 렌더러 인터페이스 일반화 → Mermaid 렌더러 → 실제 Word 검증(복원 동일성, 실행 취소, 불러오기 멈춤 없음, 떠 있는 개체·수식과의 공존).
