# 로드맵 (작업 후보와 순서)

## 완료
- 기본 왕복(Word ↔ Obsidian 마크다운), 위키링크, callout, 문단 스타일, 목록(중첩 포함)
- Word 전용 객체 보존(사이드카): 표, 이미지, 변경 추적, 각주, 필드, 떠 있는 그림/도형/텍스트 상자(OOXML)
- 수식: OMML ↔ LaTeX(직접 만든 변환기), 변환 불가 수식은 편집 가능한 그림(LaTeX 보존)
- 표: 단순 표 → GFM 표(원본 복원 + 편집 시 재구성)
- 커뮤니티 플러그인 호스트: 로더, Obsidian API 호환 계층, 에디터 연결, 설정 탭(범용), 수식 렌더링(Temml)
- 실제 Word(한국어 UI)에서 검증: Latex Suite 1.14.1 로드, 스니펫, 설정 변경

## 번들 정리 + 코드 검토 결과 (이번 라운드)
- **메인 번들 837 kB → 357.6 kB (gzip 295 → 116.5)**: 마크다운 언어 지원(`lang-markdown` 트리), 변환기·Word 연동(`word`), 플러그인 하위 시스템(`plugins-ui`)을 첫 화면 이후 지연 로딩. 전체 전송량은 비슷하고 첫 화면에 필요한 양만 줄었다. 변환기는 첫 화면 뒤에 미리 받아 두므로 첫 클릭이 느려지지 않는다.
- **제곱으로 느려지던 구간 수정**: `parseStyleNames`가 문서 전체에 `[^{}]+` 정규식을 돌려서 입력이 2배면 시간이 4배였다(147 kB HTML에서 불러오기 11.9 s → 0.44 s, jsdom 기준). `<style>` 블록 안에서만 찾도록 바꿨다. 이제 입력 크기에 비례(589 kB에서 1.6 s).
- **사이드카 재작성 생략**: 변경이 없으면 Custom XML Part를 지우고 다시 쓰지 않는다(그림·OOXML이 든 큰 파트를 매번 다시 쓰는 비용과 불필요한 문서 변경 방지).
- 검토했지만 손대지 않은 것: 불러오기 경로의 DOMParser 5회 파싱(각각 선형, 합쳐도 작음), `math.ts`(939줄, 구조는 길지만 선형이고 테스트가 촘촘함).

- **실제 Word 실측(37쪽, 표 30, 수식 60, 그림 20, 단어 1.75만)**: 불러오기 7.8 s → 4.6 s(우리 변환 0.81~1.40 s → 0.14~0.21 s, Office.js 호스트 시간 1.5~2 s 감소). 적용은 대부분 Word의 삽입 작업이라 27 s → 16~22 s 정도로 차이가 작다.
- 실측 중 발견해 고친 버그: (1) 마크다운 언어 조각을 못 받았을 때의 안내 문구가 `Office.onReady`에 덮어써지던 것, (2) Word가 `getOoxml` 호출마다 새 `rsid`/`paraId`를 넣어서 표·떠 있는 개체가 있는 문서에서는 사이드카 재작성 생략이 동작하지 않던 것(변경 없는 항목은 기존 값을 유지하도록 정규화).

## 적용 정확성 수정 (완료, `apply-fixes`)
- **큰 문서 적용 시 문단이 사라짐(771 → 741)**: 증거. 사라진 것은 **내용이 있는 문단이 아니라 빈 문단뿐**이다. 큰 문서는 표 뒤 빈 문단 30개(diff로 확인), 혼합 문서는 표 뒤 빈 문단 1개, 간격 시험 문서(35문단)는 빈 문단 13개 전부(문장 사이 1개·연속 3개·제목 앞·목록/그림/떠 있는 개체/수식 뒤·표 뒤·문서 끝 3개)가 사라졌다. 가설 (ii)(원본 빈 문단이 마크다운에 아예 나타나지 않음)이 원인이고, (i)(`next.getPrevious().delete()`)은 부분적이다: 그 줄을 끄고 시험하면 혼합 문서는 14문단이 유지되지만 표 바로 뒤에 문단이 없던 표는 불필요한 빈 문단이 생긴다(35 → 24). 즉 표지 문단 삭제는 맞는 동작이고, 빠진 정보는 마크다운에 있어야 했다.
- **수정**: 빈 문단 표지(`<!-- word:blank [n=N] -->`, README '빈 문단과 반복 적용'). 표만 사이드카 플래그로 처리하지 않고 모든 최상위 빈 문단을 한 가지 방식으로 다룬다. 이전 마크다운은 그대로 적용된다(시험: 표지를 지운 마크다운 → 이전과 같은 22문단).
- **`getHtml`의 가짜 빈 문단**: 선택 영역이 마지막 문단 표지를 포함하면 빈 문단이 하나 더 붙는다(문서 끝 빈 문단 3개 → HTML에 4개). 보정하지 않으면 적용할 때마다 문단이 하나 늘었다(35 → 36). Office.js가 센 끝의 빈 문단 수와 비교해 정확히 1개 많을 때만 뺀다.
- **적용 직후 한 번 더 적용하면 `GeneralException`**: 증거. `OfficeExtension.config.extendedErrorLogging = true`로 `debugInfo.errorLocation = "Range.getHtml"`, `statement = "selection.getHtml();"`(안전장치가 현재 선택 영역을 읽는 첫 문장). 첫 적용 뒤 선택이 문서 맨 앞의 **삽입점**(`sel 0-0 type=1`)으로 접혀 있었고, Word는 접힌 선택의 `getHtml`에서 `GeneralException`을 던진다. (정상이라 해도 `insertHtml(replace)`는 낡은 내용을 남긴 채 새 내용을 끼워 넣을 뻔했다.)
- **수정**: (1) 적용 끝에서 영역 전체를 다시 선택(경계 문단을 추적(`trackedObjects`)해 두었다가 그 사이를 선택. `insertHtml`이 돌려주는 범위나 시작점 앵커는 객체로 문단을 바꾸면 줄어들거나 끝으로 이동해서 쓸 수 없었다 — 첫 시도에서 떠 있는 그림이 2개, 3개로 늘었다). 문서 끝까지면 마지막 문단의 `Whole` 범위를 써야 마지막 문단 표지까지 포함된다(`Content.End`로 확장하면 1 모자람). (2) 선택이 비면 안내 메시지로 중단. (3) 선택이 마지막으로 불러오거나 적용한 영역(문단 텍스트의 지문)과 다르면 확인을 묻는다.
- **인수 시험(실제 Word)**: 혼합/큰/간격 문서에서 적용 3번 연속이 같은 문서(문단 덤프 동일, 개수 동일, 예외 없음), 적용 → 에디터 수정 → 적용 → 불러오기가 수정본을 돌려줌, 적용 1번을 되돌리는 데 Ctrl+Z 2번(전과 같음), 실행 취소 직후 적용은 확인을 묻고 '바꾸기'를 누르면 기대한 상태, 실행 취소 + 다시 실행 뒤 적용은 확인 없이 같은 상태, 커서만 있는 선택은 안내 메시지로 중단하고 문서 불변, 다른 영역을 선택하면 확인 → '취소'에서 문서 불변, 문단 3~9만 선택한 부분 영역 적용 3번도 같은 문서·같은 선택, 표 줄을 지운 마크다운은 여전히 거부.
- 남은 것: 목록·표 칸 안의 빈 문단과 스타일이 있는 빈 문단(빈 제목 등)은 표지 대상이 아니라 여전히 사라진다. 적용 뒤 셀 안/떠 있는 개체로만 이루어진 영역을 선택하는 경우의 `getHtml` 가짜 빈 문단 보정은 일반 문단 영역에서만 확인했다.

## 진행 순서
1. **번들 정리 + 코드 검토**: 메인 번들(≈837 kB) 축소(CM6 보조 모듈, 표/수식 코드 등 지연 로딩 가능한 부분)와 오버헤드/복잡도가 높은 코드 점검. 과한 최적화가 아니라 코드 검토 수준. 불러오기/적용 동작과 정확성이 바뀌면 안 된다.
2. **래스터화기 하드닝**: `innerHTML`로 숨긴 요소에 MathML을 넣어 크기를 재는 부분을, 정제기에 의존하지 않는 방식(DOM 노드 직접 구성 등)으로 바꾼다.

## 후보 (기억해 둘 것, 순서 미정)
3. **Mermaid 렌더러**: docs/unsupported-syntax.md의 3단계 사다리(네이티브 → 그림 + 소스 보존 → 글자 그대로)를 코드 블록 렌더러로 일반화. 렌더러는 지연 로딩, 엄격 모드, 크기·시간 상한.
4. **수식 그림의 색/크기 대응**: 지금은 검은색, 본문 11pt 고정. 문서의 글자 색/크기(어두운 배경 문서 포함)에 맞추는 옵션.
5. **마크다운 표 확장**: 병합 셀/여러 문단 셀/목록·인용 안의 표 처리, 인라인 코드 글꼴·취소선 감지.
6. **Word 전용 수식 → LaTeX 불가 수식**: 변환기 지원 범위 확대(현재는 자리표시자).
7. **Mac/웹 Word 검증**: 현재는 Windows 데스크톱 Word(한국어 UI)에서만 검증.
8. **실행 취소 1단계화**: 적용 후 Ctrl+Z가 2단계인 경우 줄이기.
9. **플러그인 호환 확대**: Vim 관련 API, 아이콘, `window.moment`, 라이브 프리뷰 렌더링 등.
10. **설치/배포**: 설치 파일(.exe) 또는 스크립트, Mac 설치 스크립트, 호스트 주소 변경(`-BaseUrl`). 당분간 보류(구현 우선).
11. **테스트 보강**: 플러그인 행/설정 패널(`plugins-ui.ts`)의 jsdom 테스트, 이미지가 든 표의 실제 Word 검증.
