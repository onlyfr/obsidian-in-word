# 구현 계획 / 작업 체크리스트

마지막 갱신: 2026-11-07. 체크 표시는 구현과 해당 검증이 끝났을 때만 갱신한다. 실행 중인 작업, 남은 제약과 다음 순서를 여기에 기록한다.

## 원칙

- 현재 Word 본문의 MD 표현 ↔ Word 표현 전환 경험을 중심에 둔다.
- MD→Word 렌더링 품질을 우선하며 Word→MD는 가능한 마크다운 표현을 추출한다.
- 실패 시 자동 편집을 정지하고 Word Undo/Redo를 사용한다. 별도 복구 UI와 자동 롤백은 추가하지 않는다.
- 최종 앱은 npm/개발 서버/GitHub Pages 없이 실행하는 네이티브 형태다. 현재 웹 작업창과 시험 RPC는 중간 검증 환경이다.

## 1. 본문 편집 시작 / 중지 — 완료 (PR #35)

- [x] 현재 네이티브 호스트 연결을 실사용 컨트롤러에 주입하는 경계 정의. 인증된 시험 RPC를 제품 API로 그대로 노출하지 않음.
- [x] 시작 시 선택한 일반 문단을 명시적으로 등록. 다른 애드인 컨트롤·중복 ID는 가져오지 않음.
- [x] 시작 / 중지 버튼과 꺼짐·연결 중·등록 중·준비됨·입력 대기·중지됨 상태 표시. 실제 MD 편집 중 표시는 2단계에서 연결.
- [x] 실제 IME 상태·문서 소유권 연결이 없으면 시작하지 않음. idle을 가정하는 대체 경로는 만들지 않음.
- [x] 중지 시 새 전환을 예약하지 않고 진행 중 작업의 결과를 확인. 임의의 본문 롤백은 하지 않음.
- [x] 실제 Word에서 시작·중지·반복 시작과 연결 종료 시험.

- [x] 커밋·푸시·main 반영: https://github.com/onlyfr/obsidian-in-word/pull/35

이번 단계의 경계: 호스트를 명시적으로 주입한 환경에서만 준비 컨트롤을 표시한다. 현재 웹 작업창은 localhost 탐색이나 시험 RPC 자동 연결을 하지 않는다. 사용자가 시작을 누른 뒤 Word 본문에 포커스가 돌아와 실제 idle을 확인해야 문단을 등록한다. 이 단계에서 문단을 MD로 다시 쓰지 않는다.
