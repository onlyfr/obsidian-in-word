# Desktop Word acceptance tests

Run `npm run test:word` on Windows with Word closed. The runner creates its own synthetic document, starts Word through COM, loads the real source through an HTTPS task pane, runs the cases, closes its document without saving, unregisters its unique test add-in, and stops the server. It does not change the production manifest registration. Do not edit Word during the run.

Prerequisites:

- Installed desktop Word, Node, Python 3.9+, and `npm install` for this repository.
- Trusted Office development certificates at `~/.office-addin-dev-certs/localhost.key` and `localhost.crt`. Use your existing Office development setup; this runner does not install certificates or bypass trust prompts.
- Cached `office-addin-dev-settings` (tested with 4.0.1). If absent, run `npx --yes office-addin-dev-settings@4.0.1 --help` once. The runner finds its template/CLI in the default npm cache. For a custom installation, use `python scripts/word-host/run.py --dev-settings-dir PATH_TO_PACKAGE`.
- Network access to Microsoft's hosted `office.js`.

Results, timing, server logs and the fixture are saved under ignored `test-docs/word-host/<run>/`. `report.md` summarizes the run; `results.jsonl` and `com-results.jsonl` contain the observations. A failed assertion exits unsuccessfully and still attempts cleanup. There are bounded timeouts; a Word/add-in startup failure may need manual cleanup (see `word.log`). The helper PowerShell process remains hidden; Word itself is visible.

The cases cover three repeated mixed-document applies; missing-original refusal before mutation; native equation insertion failure after table/float insertion; optional style failure; undo with/without styles and after failure; a 100-day-old long math-picture source surviving another region's load; 12 inline/display raster samples; and three applies of a synthetic 300-paragraph/30-table/60-equation document.

For raster regressions, `npm run test:word -- --compare-raster-ref 8f21f46` also renders the corpus with that commit's `mathraster.ts` in the same Word browser and compares dimensions, baseline and PNG bytes exactly. The argument must be a commit hash available locally. The runner copies only that source file into the ignored run directory and rewrites its two imports to use the current math image helpers/Temml renderer. This compares raster layout/DOM assembly under the same dependencies, not whole historical application versions. Without the option, the corpus checks rendering and PNG output without a historical comparison.

The fault cases temporarily intercept Office.js setters/method arguments and send a nonexistent style or invalid OOXML to **real Word**. They restore the methods in `finally`. No mock host is used. Undo checks compare text and object counts, not every formatting property. These tests do not establish compatibility with Mac, web Word, arbitrary user documents, or every Office build. The measured large fixture has no ordinary pictures and is not the former 37-page benchmark.

Additional cases switch hybrid math -> all images -> hybrid, checking LaTeX/display flags, cached PNG bytes and stable paragraph counts. A development-only body-editing probe wraps one ordinary paragraph in a content control and uses `Office.EventType.DocumentSelectionChanged`: entering exposes Markdown in the Word body, a COM text edit changes the source, and leaving renders bold/italic again. It checks two transitions without a feedback loop and removes the handler. This is a feasibility experiment, not a production editor. IME input, arbitrary paragraphs/objects, rapid moves, undo, document reload and coauthoring are not covered by that probe.

`client.html` is a development-only entry point and is not referenced by the production task pane/build. Commands originate in local files written by the runner; the default local server has no endpoint accepting scripts. The opt-in native-flow transport below accepts fixed authenticated operations only.

`npm run test:word -- --body-session-only` runs the focused session lifecycle suite. It uses the host-independent `src/body/session.ts` with the experimental Word adapter: stable ID/revision checks, document Custom XML recovery records, coalesced requests, a simulated composition gate, explicit current/original recovery, partial-write interruption, actual document save/close/reopen with a fresh task-pane runtime, native undo/redo and deleted-control guards. It does not simulate a real IME or wire this controller into the production UI. The test server suppresses already-completed commands after a task-pane reload so document reopen cannot replay a previous mutation case.


`npm run test:word -- --body-input-only` is a separate foreground keyboard probe. Close Word first and avoid interacting with the computer during the short run. It activates only its synthetic Word window and sends actual virtual-key down/up events, checking the foreground process and root window before every key; a focus change aborts input. It uses existing keyboard layouts only and restores the previous layout/mode where observable. It never installs layouts or changes registry settings. The standard suite does not send keyboard input.

This probe checks a caret inside bold text, noncollapsed selection, Korean/emoji UTF-16 positions, actual Q/W/E input, Korean two-set R/K/S/K/E/K plus Space, and the unknown-composition gate. Results are in `input-summary.json`. Inspect `ActualCompositionVerified` separately: committed Hangul does not prove that IME composition start/end was observed. On the measured Word build, external IMM32 returned no context. The test explicitly signals idle after Space; there is no automatic native IME bridge or production event connection. Systems without the needed Korean input/layout do not establish the same coverage.


Add `--native-ime` to the foreground probe to compile/attach the development x64 TSF observer (Visual Studio C++ and Windows SDK required). This path receives real `OnEndEdit` composition states through a local SSE stream and verifies rendering on COM selection exit **without a manual idle signal**, plus no selection queries while active/unknown and a closed gate on disconnect. `native-ime.jsonl` distinguishes edit notifications from health snapshots. The older IMM32 result remains separate. See [native observer](../../native/word-ime/README.md) for lifetime, cleanup and asynchronous transport limitations. The observer unadvises sinks/removes hooks on stop; its callback DLL remains pinned until the owned Word process exits.


`--format-only` runs five Markdown → real Word → Markdown cycles covering redundant/nested emphasis, strike, lists and mixed Latin/Korean runs. It also runs in the full suite. `--native-guard-only` builds the native checked-source-write primitive and tests stale text/XML/identity/epoch/sequence rejection, unsupported multiline/change tracking, unknown focus, and successful idle replacement. No keys are injected in that mode. With `--body-input-only --native-ime`, a prebuilt write request is additionally submitted during real Korean composition and must be rejected before touching Word text.


`npm run test:word -- --native-flow-only` builds and tests integrated native entry/render, mapped caret/selection, stable paragraph/neighbor preservation, three repeated transitions, undo/redo with read-only recovery inspection, failures after journal/content/tag, closing-content interruption, actual save/close/reopen with fresh runtime/observer, stale-epoch refusal and Unicode/code formatting. It injects no keys, but foreground/focus changes can deliberately refuse a mutation. Setup cases activate only the owned fixture; RPC operations do not change foreground focus. The suite saves `native-flow-summary.json`. It supplies `NativeBodyHost` through an authenticated fixed-operation test RPC; this adapter is not part of the shipped task pane. The first entry/exit also replace `Word.run` with a throwing stub to ensure that those transitions do not silently fall back to Office.js.

`npm run test:word -- --native-selection-only` enables explicit ownership mode and adds fixed selectedKey/candidate/claim operations to that authenticated transport. It enrolls two ordinary paragraphs, subscribes to native Word selection events (Office.js selection subscriptions and `Word.run` are replaced by throwing stubs), and checks automatic source/render transitions, rapid moves, no health polling/feedback loop, foreign controls and unsupported formatting refusal, native ownership-ID/duplicate-tag rejection without journal writes, save/reopen and deletion. It saves `native-selection-summary.json`. This mode sends no keys but requires document focus. Older flow/guard fixtures deliberately use legacy tagged controls without the registry; they do not establish ownership coverage.

`npm run test:word -- --native-format-only` checks concrete font names (including East Asian and complex-script slots), half-point sizes and RGB colors across two native round trips and a local text edit. It destroys the HTTP response after the worker completes to simulate actual reply loss, checks that the session pauses without replay, and uses Word COM Undo/Redo to restore the document. It also interrupts source entry after the text mutation and checks Word Undo restores typography. No application recovery API is used by this suite. Source-entry Undo can leave the source tag behind even after text/format restoration; the stopped session is intentionally not resumed. `native-format-summary.json` records actual Undo counts. Tests send no keys and require document focus. New recovery UI/automatic rollback is out of scope by user decision.

The selection suite also delays completion of a real B render, moves B → A → B while that conversion remains pending beyond the debounce, and checks that B re-enters source from a fresh selection read. This covers notifications arriving during a conversion rather than only during selection queries.

`npm run test:word -- --settings-ui-only` mounts the real task-pane markup/module inside the owned Word WebView, checks the native modal and tab keyboard navigation, applies/saves editor/math choices, loads a synthetic plugin through the file UI, opens its settings via a plugin command, and verifies hide/cleanup, enable/disable/delete and unchanged Word content. It sends no physical keys and needs no foreground keyboard window. It saves `settings-ui-summary.json`.

`npm run test:word -- --body-controls-only` explicitly installs the authenticated development bridge into the real task pane, checks start/stop/restart and idempotent enrollment, stops the actual native observer to verify disconnection, reattaches it, and delays a committed claim response while Stop is pressed. Stop must remain pending until the outcome is known and issue no further selection reads or claims. Two paragraphs get exactly two claims. A third paragraph tests response loss after Stop: one claim, error with Word Undo guidance, and no replay. Source/render/rollback are never requested, and paragraph text/formatting stay unchanged. Provider removal hides the controls. The suite saves `body-controls-summary.json`. It sends no keys but registration needs Word document focus. The fixed connection-metadata operation performs no selection read; the worker additionally refuses requests when its scoped document is not active. The HTTP adapter remains in scripts/ and is not part of the production entry point.

Run direct MathJax TeX input, bundled glyph, raster corpus, hybrid/images round-trip and alignment-coordinate checks with: npm run test:word -- --math-only. The runner saves math-summary.json, latex-font.png and math-alignment.png, and sends no keyboard input. Alignment cases compare equal-sign coordinates for unequal row lengths and preserve original ampersands on Word round-trip.

`npm run test:word -- --body-check-only` checks the real read-only status button, owned/unregistered selections, actual Word Undo→inspection→Redo, and a tagged-stage native failure. Undo leaves a source tag/unfinished journal: inspection must refuse without writes and preserve Redo. A later start on another paragraph must refuse without claiming. The suite saves `body-check-summary.json`, uses only its scoped synthetic document, and sends no keys. It requires native Word document focus.

Compare PNG bytes, dimensions and baselines against a local commit (including that commit's MathJax adapter) with `npm run test:word -- --math-only --compare-raster-ref 83a9d87`. For the separate CPU-only SVG benchmark use `npm run bench:math-svg -- 83a9d87` with Node >=22.18. It compares 80 serialized SVGs, alternates five timed rounds after warmup, and saves JSON under ignored `test-docs/math-bench/`. It does not measure PNG generation or Word document insertion.

`npm run test:word -- --identity-only` checks individual/paragraph/whole selections, mixed ordinary images and equations, table package preservation, three applies, save/reopen, unchanged sidecar Part IDs and image appearance. `object-identity` and `math-appearance` also run in the default full suite. `npm run bench:objects -- 9037419` measures only OOXML scanning/paragraph capture against the local baseline and saves JSON in ignored `test-docs/object-bench/`; it does not measure total Word apply speed.
