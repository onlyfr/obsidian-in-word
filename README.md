# obsidian-in-word

Microsoft Word 안에서 Obsidian 스타일 마크다운(위키링크, callout, frontmatter, 수식 등)으로 편집할 수 있게 해 주는 Word 애드인 프로젝트입니다.

> **면책 / Disclaimer**
> 이 프로젝트는 Microsoft 및 Obsidian과 **무관한 비공식 개인 프로젝트**입니다. Word를 더 편하게 사용하려고 개인적으로 만들고 있습니다.
> This is an unofficial personal project, not affiliated with or endorsed by Microsoft or Obsidian. "Word" and "Obsidian" are trademarks of their respective owners.

## 목표

최종 목표는 **Word 본문에서 바로** Obsidian 마크다운과 호환 플러그인으로 편집하는 것입니다. 현재 작업창 에디터는 그 목표를 위한 중간 단계이며, 변환·객체 보존 엔진을 먼저 검증하고 있습니다. 구현 방향은 [로드맵](docs/roadmap.md)에 기록합니다.

최종 제공 형태는 **네이티브 앱**이며, 사용자가 npm 명령이나 GitHub Pages 없이 설치·실행할 수 있도록 하는 것이 목표입니다. 원본 모드와 실시간 미리보기 전환을 편집 경험의 참고로 삼습니다. 아래 웹 애드인 개발·배포 방식은 현재의 중간 검증 환경이며, 최종 네이티브 호스트와 설치 방식은 추후 결정합니다.

- Word 객체 ↔ Obsidian 마크다운을 상호 변환 가능한 단위로 정의하고 관리
- 마크다운으로 표현할 수 없는 Word 전용 객체는 메타데이터(사이드카)로 보존
- CodeMirror 6 기반 편집 환경에서 호환되는 커뮤니티 확장(예: Latex Suite 같은 편집/문법 계열) 사용

## 상태

Windows 데스크톱 Word에서 검증 중인 PoC입니다. 선택 영역의 마크다운 왕복 편집, Word 객체 보존, 수식·표 편집, 커뮤니티 플러그인 로딩과 설정 UI가 구현돼 있습니다. Word 본문의 직접 마크다운 편집은 개발용 네이티브 실험으로 검증 중이며 제품 UI에는 아직 연결하지 않았습니다.

2026-11-07 기준 단위 테스트 **492개**와 타입체크·빌드가 통과했습니다. 실제 Word `16.0.20527.20112`에서도 스크립트 기반 인수 시험을 수행했습니다.

- 굵게·기울임·취소선·목록·한글/영문 혼합의 5회 왕복에서 서식 기호가 늘지 않음
- 표·수식·떠 있는 도형·빈 문단·인용 스타일 혼합 문서의 3회 반복 적용과 마크다운 왕복
- 누락 원본의 적용 전 차단, 삽입 실패 시 중복 방지, 스타일 오류 경고, 다른 영역의 오래된 수식 원본 보존
- 수식 래스터화기 변경 전후 샘플 12개의 크기·기준선·PNG 바이트 일치
- 대형 합성 문서(Office.js 300문단·표 30개·수식 60개)의 3회 반복 적용

시험 방법과 한계는 [Word 시험 도구](scripts/word-host/README.md), [문서 보존 실측](docs/testing/2026-11-06-word-host.md), [래스터화기 검증](docs/testing/2026-11-06-mathraster-dom.md)을 참고하세요. Mac/웹 Word는 아직 검증하지 않았습니다.

본문 편집은 개발용 실험에서 일반 문단의 소스 전환, 상태 추적, 문서 재열기 후 복구, 실행 취소/다시 실행과 삭제 가드를 확인했습니다. 실제 키 입력·한글 확정 입력·커서/선택 범위 보존도 [입력 검증 기록](docs/testing/2026-11-06-body-input-and-caret.md)에 남겼습니다. 개발용 네이티브 TSF 관찰기로 실제 IME 조합 신호를 연결했고, 단절되거나 상태가 불명확하면 전환을 멈춥니다. [신호 연결 검증 기록](docs/testing/2026-11-06-native-ime-bridge.md)에 결과와 비동기 전달의 한계를 남겼습니다. 일반 문단의 소스 전환·서식 복원·선택 보존·단계별 복구 기록을 네이티브 포트에 연결했습니다. 실제 Word에서 반복 전환과 저장·재열기 후 복구, 한글·이모지·코드 서식과 커서 보존을 확인했습니다. [네이티브 통합 기록](docs/testing/2026-11-06-native-body-transitions.md)에 범위와 결과를 남겼습니다. 전체 run 서식·다양한 IME·재진입 경합 검증은 계속 필요합니다. 복합 객체·공동 편집까지 검증하기 전에는 제품 UI에 노출하지 않습니다.

명시적으로 등록한 문단은 Word의 네이티브 선택 이벤트로 소스/서식 상태를 자동 전환합니다. 문서에 블록 키와 컨트롤 ID를 함께 저장하며, 다른 애드인의 컨트롤이나 복제된 태그를 자동으로 가져오지 않습니다. 실제 Word의 두 문단 이동·저장 후 재열기·ID 충돌·삭제 검증은 [선택 이벤트와 소유권 기록](docs/testing/2026-11-06-native-selection-ownership.md)을 참고하세요.

네이티브 실험에서는 명시적인 글꼴 이름·RGB 색상·글자 크기도 소스 왕복 때 보존합니다. 텍스트를 한 서식 구간 안에서 고치면 그 서식을 이어받고, 서로 다른 원본 서식 사이에서 판단이 모호한 편집은 소스를 남기고 멈춥니다. 실패 후 복구는 **Word의 Ctrl+Z / Ctrl+Y에 의존**하며, 별도 복구 UI는 추가하지 않습니다. 여러 번 되돌려야 할 수 있고, 내부 태그가 남을 수 있어 실패 후 자동 재개하지 않습니다. 범위와 실측은 [서식·Undo 기록](docs/testing/2026-11-07-native-run-format-undo.md)에 남깁니다.

## 개발 (PoC)

Word 작업창의 CodeMirror 6 에디터로 선택 영역을 불러와 편집한 뒤, 같은 영역에 적용합니다. `markdown-it`·`turndown` 기반 변환에 OOXML 객체 복원, OMML 수식 변환, 표 재구성, 빈 문단 보존을 결합합니다.

```bash
npm install
npm test        # 변환·플러그인 호환·적용 안전장치 등 단위 테스트
npm run build   # 타입체크 + 번들
npm run test:word # 실제 Windows Word 자동 인수 시험 (사전 설정: scripts/word-host/README.md)
```

실제 Word 시험은 Word를 닫고 실행하세요. 시험 전용 문서를 자동으로 만들며, 종료 후 Word·서버·임시 애드인 등록을 정리합니다. 증거와 실행 시간은 gitignore 대상인 `test-docs/word-host/<실행 디렉터리>/`에 남습니다.

### 기본 사용 순서

1. Word에서 편집할 영역을 선택하고 **선택 영역 → 마크다운**을 누릅니다.
2. 작업창에서 마크다운을 편집합니다. 표지 줄은 원본 객체·스타일·빈 문단 복원에 사용됩니다.
3. **Word에 적용**을 누릅니다. 완료 후에는 적용 영역이 다시 선택되어, 그대로 수정·적용을 반복할 수 있습니다.
4. 다른 영역을 선택하면 교체 확인을 묻고, 커서만 있는 선택은 적용을 거부합니다. 실패 안내가 나오면 아래 실행 취소 안내를 따르세요.

### 로컬 서버 없이 사용 (GitHub Pages)
`main`에 푸시하면 GitHub Actions가 테스트·빌드를 거쳐 [GitHub Pages](https://onlyfr.github.io/obsidian-in-word/)에 정적 파일로 배포합니다. 이 경우 로컬 서버나 인증서 없이 `manifest.prod.xml`을 Word에 사이드로드하면 됩니다. 코드는 Word 작업창 안에서 실행됩니다.

사전 설정: 저장소 Settings → Pages → Source를 **GitHub Actions**로 지정해야 합니다.

### 개발용 로컬 서버
코드를 수정하며 바로 확인하려면 HTTPS 개발 서버와 `manifest.xml` 사이드로드가 필요합니다.

1. `certs/localhost.key`, `certs/localhost.crt`를 준비합니다 (예: `mkcert localhost`).
2. `npm run dev` 로 `https://localhost:3000` 서버를 띄웁니다.
3. `manifest.xml`을 Word에 사이드로드합니다 ([Microsoft 문서](https://learn.microsoft.com/office/dev/add-ins/testing/test-debug-office-add-ins) 참고).

### Word 전용 객체 보존
표, 이미지, 도형, 변경 추적, 각주, 필드 등 마크다운으로 표현할 수 없는 블록은 편집기에서 `<!-- word:obj id=… kind=… -->` 한 줄로 보입니다. 원본은 문서 안의 Custom XML Part(사이드카)에 id별로 저장되고, "Word에 적용" 시 그 자리에 복원됩니다. 자리표시자를 옮기면 객체도 따라 움직입니다. 일부 객체는 표지를 지우면 삭제되지만, 선택 영역의 표·수식·떠 있는 개체 수가 줄어드는 적용은 손실 방지 장치가 거부합니다.

사이드카는 문서 전체가 공유합니다. 다른 영역에서 쓰는 원본을 지우지 않도록 날짜·용량에 따른 자동 삭제는 하지 않습니다. 원본이 누락된 자리표시자가 있으면 문서를 바꾸기 전에 적용을 중단합니다. 개체 복원 중 오류가 나면 이미 실행된 삽입을 재시도하지 않고 실패를 알립니다. 이 경우 Ctrl+Z를 여러 번 눌러 적용 전 상태로 되돌리세요.

서식 왕복에서 중첩된 `<b><strong>` 같은 동등 태그를 한 번만 변환하고, Word가 나눈 인접 강조 run을 합칩니다. 굵게+기울임의 중첩 순서는 일관되게 내보내며 취소선은 `~~...~~`로 보존합니다. 글자로 입력한 기호는 이스케이프해 서식으로 재해석되지 않게 합니다. 변경 추적과 보존 객체의 원본은 이 정리에서 제외합니다.

### 스타일과 위키링크
- 일반 문단은 Word의 Normal 스타일(`MsoNormal`)로 들어가고, 그 외 문단 스타일(인용, 사용자 정의 등)은 문단 앞의 `<!-- word:style class=… name=… -->` 한 줄로 보존됩니다.
- `[[위키링크]]`는 하이퍼링크가 아니라 **글자 그대로** Word에 들어갑니다. 왕복해도 `[[ ]]`가 유지됩니다.

### 수식 (Word 수식 ↔ `$…$` / `$$…$$`)
작업창의 **수식 출력**에서 다음 중 선택할 수 있습니다. 선택은 이 애드인 출처의 브라우저 저장소에 보관되며, 다음 적용부터 사용합니다. 문서별 설정은 아닙니다.

| 선택 | 적용 방식 |
| --- | --- |
| Word 수식 우선 (기본) | 편집 가능한 Word 수식(OMML)으로 만들고, 변환하지 못하는 LaTeX는 그림으로 표시 |
| 모두 그림 | 마크다운에서 편집 가능한 모든 수식을 PNG로 표시. 다시 불러오면 LaTeX로 편집 가능 |

OMML은 Word 수식 형식이며 ONNX와는 다릅니다. 두 모드를 다시 바꿔 적용할 수 있고, 같은 수식의 그림은 저장된 PNG를 재사용합니다. 그림 생성이 실패하거나 한도를 넘으면 경고와 함께 LaTeX 원문을 남깁니다. 표·변환 불가 Word 수식 등 **원본 보존 블록 내부**는 이 설정의 대상이 아닙니다. 작업 중에는 불러오기·적용·수식 출력 선택을 잠가 중복 실행을 막습니다.

Word의 `getHtml`은 수식을 그냥 GIF `<img>`로만 내보내므로(OMML 없음), 수식 원본은 같은 범위의 OOXML(`getOoxml`)에서 읽어 HTML의 이미지와 순서로 짝지읍니다. 짝이 맞지 않으면(표 안 등) 수식을 건드리지 않고 적용을 중단합니다.

- **불러오기**: OMML → LaTeX 변환(자체 구현, 외부 라이브러리·MML2OMML.XSL 미사용). 문단 안의 수식은 `$…$`, 독립 수식(`m:oMathPara`)은 `$$ … $$` 블록. 원본 OMML은 LaTeX를 키로 사이드카(`kind=math`)에 저장됩니다.
- **적용 (Word 수식 우선)**: 고치지 않은 수식은 저장된 원본 OMML을 **바이트 그대로** 복원하고, 새로 쓰거나 고친 LaTeX는 LaTeX → OMML로 변환해 `insertOoxml`로 넣습니다(편집 가능한 실제 Word 수식). 모두 그림 모드에서는 PNG 출력 경로를 사용합니다.
- **안전장치**: 선택 영역의 수식(Word 수식 + 아래 수식 그림)이 마크다운의 `$…$`보다 많으면 적용을 중단합니다. `$` 문자 그대로의 텍스트는 `\$` 로 이스케이프됩니다.

#### OMML로 바꿀 수 없는 LaTeX: 그림으로 넣고 계속 편집 (사다리 2단계)
`\boxed`, `\cancel`, `\xrightarrow`, `\color`, `\mathcal`, `\cfrac`, `\pmod`, `\substack`, `\tag` 처럼 Temml은 그리지만 자체 LaTeX → OMML 변환기가 못 하는 수식은 더 이상 적용을 막지 않습니다. 순서는 **① Word 수식(OMML) → ② LaTeX를 그린 PNG 그림 → ③ `$…$` 소스 글자(노란 표시 + 상태창 경고)**.
- **그림**: Temml MathML을 SVG `foreignObject`에 넣어 캔버스로 그린 3배 해상도 투명 PNG(글자색 검정 고정, 본문 11pt 기준 크기). 인라인 수식은 `w:position`으로 글자 기준선에 맞추고, 독립 수식은 가운데 정렬 문단입니다. 600px(약 6.25in)보다 넓으면 비율을 유지해 줄입니다. Temml과 그리기 코드는 필요할 때만 내려받는 별도 청크이며, 현재 메인 번들은 약 358.31 kB(gzip 116.80 kB)입니다.
- **짝 저장**: 사이드카 `kind=mathimg`(id = 해시(LaTeX, 독립/인라인, 렌더 버전))에 LaTeX·PNG·크기·기준선을 저장하고, 그림의 대체 텍스트는 `owb:math:<id>[:d] <LaTeX 앞부분>`입니다. 일반 그림이나 Word 수식 그림(`~WRS…`)과 섞이지 않습니다.
- **불러오기**: 이 표지가 있는 그림은 `$…$` / `$$…$$`로 다시 나타납니다(사이드카가 없으면 잘리지 않은 대체 텍스트의 LaTeX 사용). **적용**: 고치지 않았으면 저장된 PNG를 그대로 복원(다시 그리지 않음), 고쳤으면 OMML을 먼저 시도하고 안 되면 다시 그립니다.
- **한도**: LaTeX 2000자, 그림 1200×600px(1x), PNG 300 kB, 한 수식 8초·한 번의 적용 40초. 넘거나 렌더러를 불러오지 못하면 ③으로 떨어집니다(내용은 항상 남습니다). Temml도 못 그리는 LaTeX(알 수 없는 명령 등)도 ③입니다.
- **실제 Word(데스크톱, 한국어 UI)에서 확인함**: 인라인 그림이 `w:position`(−5~−14pt)으로 기준선에 맞고, 독립 수식은 가운데 정렬이며, 대체 텍스트·위치가 저장 후 다시 열어도 유지되고, 고치지 않은 수식의 PNG는 적용 후에도 바이트가 같습니다. 표·목록·떠 있는 그림·일반 그림·Word 수식·추적 변경과 한 선택 영역에서 공존하고, 불러오기→적용→불러오기 마크다운이 같습니다. 실행 취소 횟수는 아래 안내를 참고하세요. 한계: 본문이 11pt가 아니거나 글자색이 검정이 아니면 그림 크기·색이 맞지 않습니다.

### 표 (Word 표 ↔ 마크다운 표)
단순한 표는 편집 가능한 GFM 파이프 표로 나타납니다. 표 위에 `<!-- word:table id=… -->` 한 줄이 붙고(지우지 마세요), 원본 표의 OOXML은 사이드카에 그 id로 저장됩니다.

- **단순한 표**: 병합 셀·중첩 표가 없고, 모든 행의 칸 수가 같고(최대 30열 × 500행, 칸당 2000자), 각 칸이 서식 없는 한 문단(굵게/기울임/링크/줄바꿈 정도)뿐인 표. 이미지·수식·떠 있는 개체·필드·각주·변경 추적·메모가 든 표, 칸 안에 문단이 여러 개인 표(문단 경계를 `<br>`로 바꾸면 되돌릴 때 구조가 달라지므로), 목록/인용 안의 표는 지금처럼 `<!-- word:obj … kind=table -->` 자리표시자로 남습니다.
- **머리글**: 첫 행이 항상 마크다운 머리글입니다(GFM 규칙). Word의 머리글 행 표시(반복·굵게·음영)는 원본에 남아 있다가 다시 반영됩니다. 머리글의 굵은 글씨는 `**`로 보이지 않습니다. 열 정렬은 본문 칸의 정렬(`:---:`, `---:`)로 표시됩니다.
- **`|`와 줄바꿈**: 칸 안의 `|`는 `\|`, 줄바꿈(Shift+Enter)은 `<br>`로 보입니다.
- **고치지 않은 표**는 저장된 원본 OOXML 그대로 복원됩니다(서식·너비·테두리·음영·스타일 모두. Word가 삽입 때 지우는 중복 속성 `w:tblPrEx`, 문단/리비전 id 외에는 동일).
- **고친 표**는 원본을 틀로 다시 만듭니다. 유지: 표 속성(스타일·너비·테두리·들여쓰기), 열 너비, 행 속성(머리글 행·높이), 칸 속성(음영·테두리·여백·세로 정렬), 칸의 문단 속성과 기본 글꼴, 그리고 **텍스트가 바뀌지 않은 칸은 원본 서식 그대로**. 바뀐 칸은 마크다운으로 표현되는 서식(굵게·기울임·취소선·코드·링크·줄바꿈)만 갖습니다. 새 행은 마지막 행을, 새 열은 마지막 열을 복제하고, 열을 지우면 표 너비가 줄어듭니다. 표지가 없는 새 표는 테두리 있는 기본 표(굵은 머리글 행)로 만들어집니다.
- **안전장치**: 머리글보다 칸이 많은 행(글자가 사라질 수 있음), 표지만 있고 표가 깨진 경우, 표 줄을 지워 선택 영역의 표 수가 줄어든 경우에는 적용을 중단합니다. 짧은 행은 빈 칸으로 채우고 상태줄에 알립니다. 실행 취소 횟수는 아래 안내를 참고하세요.

### 빈 문단과 반복 적용
- **빈 문단(간격용)**: 마크다운에서 빈 줄은 문단 구분일 뿐이라 빈 문단을 나타낼 수 없습니다. 그래서 본문의 빈 문단은 `<!-- word:blank -->` 한 줄(연속이면 `<!-- word:blank n=3 -->`)로 나타나고, 적용하면 같은 수만큼 빈 문단으로 돌아갑니다(최대 50개). 표·그림·수식·목록 뒤, 연속, 문서 끝의 빈 문단도 마찬가지입니다. 표 바로 뒤의 빈 문단도 이 표지로 보존되며, 표지가 없는 예전 마크다운은 이전과 똑같이 적용됩니다(빈 문단 없음). 목록·표 칸·특수 스타일(제목 등) 안의 빈 문단은 대상이 아닙니다. 선택 영역이 마지막 문단 표지를 포함하면 `getHtml`이 없는 빈 문단 하나를 더 붙이는 것(실측)을 보정해서 표지가 하나 늘어나지 않습니다. 단점: 빈 문단이 많은 문서는 표지 줄이 보입니다.
- **같은 영역 반복 적용**: '적용'을 마치면 적용한 영역 전체가 다시 선택된 상태가 되어, 에디터를 고치고 다시 누르면 같은 영역을 바꿉니다(불러오기 없이 여러 번 가능, 결과는 같은 문서). 선택이 커서만 남았으면(비어 있으면) 예외 대신 안내 메시지로 중단합니다. 선택 영역이 마지막으로 불러오거나 적용한 영역과 다르면(다른 곳을 선택했거나 실행 취소 직후) '바꾸기 / 취소' 확인을 묻고, 취소하면 아무것도 바꾸지 않습니다. 표·수식·떠 있는 개체 개수 안전장치는 그대로입니다. 실행 취소 횟수는 아래 안내를 참고하세요.

### 커뮤니티 플러그인 호스트 (초기)
작업창의 **플러그인 (Obsidian 커뮤니티)**에서 `manifest.json`과 `main.js`를 함께 선택해 불러옵니다(`styles.css`는 선택). 켜기·끄기·삭제, 명령 실행·단축키, 설정 탭과 호환성 보고서가 연결돼 있습니다. 플러그인 번들은 IndexedDB에, 설정은 localStorage에 저장하며 저장소를 사용할 수 없으면 메모리로 동작합니다.

`src/plugins/host.ts`가 CommonJS 모듈과 에디터 확장을 로드하고 Obsidian API 일부를 제공합니다. Latex Suite 1.14.1의 로딩·스니펫·설정 변경은 실제 Word 작업창에서 검증했습니다. 모든 Obsidian 플러그인이나 파일/vault API가 지원되는 것은 아닙니다. 플러그인은 Office.js에 접근할 수 있는 코드를 그대로 실행하므로 신뢰하는 것만 사용하세요. 상세 범위는 [호환 계층 메모](docs/plugin-compat.md)의 검증 항목을 참고하세요.

### 실행 취소와 적용 실패

Windows Word 자동 시험에서 적용 전 본문 텍스트와 객체 수로 돌아오는 데 필요한 실행 취소는 다음과 같았습니다.

| 시험 조건 | 실행 취소 횟수 |
| --- | --- |
| 별도 스타일 복원 없는 정상 적용 | 2번 |
| 인용 스타일 복원이 있는 정상 적용 | 3번 |
| 표·도형 복원 뒤 수식 삽입 강제 실패 | 2번 |

문서와 실패 위치에 따라 횟수는 달라집니다. 실패한 적용은 일부 작업이 이미 실행된 상태일 수 있고 자동 롤백은 하지 않습니다. **실패 안내가 나오면 Ctrl+Z를 여러 번 눌러 적용 전 상태를 확인하세요.** 스타일 적용은 개체 복원 뒤 별도 실행하며, 실패 시 경고를 표시하고 개체를 재삽입하지 않습니다.

### 알려진 한계
- 불투명 블록 안의 텍스트는 마크다운으로 편집할 수 없습니다 (이미지가 한 장이라도 들어 있는 문단 전체가 하나의 블록이 됩니다).
- 일반 텍스트의 HTML 변환과 일부 불투명 블록은 Word 고유 서식을 잃을 수 있습니다. 떠 있는 개체·수식·원본 표는 OOXML/OMML로 복원하지만 모든 문서 서식의 무손실을 보장하지는 않습니다.
- 문서 전체 참조를 확인하는 정리 기능이 없어 사이드카의 불필요한 항목이 누적될 수 있습니다. 날짜·용량만으로 원본을 자동 삭제하지 않습니다.
- 검증 범위는 Windows Word의 시험 문서와 기록된 유즈 케이스입니다. 임의 사용자 문서의 모든 객체·서식과 Mac/웹 Word는 추가 검증이 필요합니다.
- Word 본문에서 직접 타이핑할 때는 CM6 확장(스니펫 등)이 동작하지 않고, 작업창 에디터 안에서만 동작합니다.
- 수식은 LaTeX로 바꿀 수 있는 범위(분수, 첨자, 합/적분, 근호, 괄호, 행렬, 악센트, 함수, 그리스 문자, `\text`)만 편집할 수 있습니다. 그 밖의 **Word 수식**(박스, 위상 기호 등)은 LaTeX를 만들어 낼 수 없으므로 그 문단 전체가 `<!-- word:obj … kind=equation -->` 로 보존됩니다(반대 방향, 즉 마크다운의 `$…$`는 위 사다리를 따릅니다). 수식 그림이 표 안에 있으면 풀지 못하고 적용이 중단됩니다. 표 안의 수식과, 수식을 지우는 적용은 중단됩니다. 표 칸 안의 `$…$`는 수식이 아니라 글자로 들어갑니다.
- 수식 그림은 본문 11pt·검정 기준입니다. 문서 글자 크기·색에 맞추는 옵션과 Mermaid 렌더러는 아직 구현하지 않았습니다.
