# Obsidian in Word

Windows용 Microsoft Word에서 선택한 문단을 **Obsidian 스타일 마크다운으로 편집한 뒤 문서에 다시 적용**하는 앱입니다. Word 옆 작업창에서 제목·목록·강조·표·LaTeX 수식을 고칠 수 있습니다. 마크다운으로 표현하기 어려운 도형과 복합 표는 원본 Word 개체로 보관합니다.

## Windows에서 시작하기

1. [Windows 빌드 목록](https://github.com/onlyfr/obsidian-in-word/actions/workflows/windows-build.yml)에서 성공한 최신 `main` 실행을 열고 **Artifacts → windows-app**을 다운로드합니다. 다운로드 항목을 보려면 GitHub 로그인이 필요할 수 있습니다.
2. 다운로드한 압축을 풉니다. 안에 있는 `obsidian-in-word-windows.zip`도 풀고 **ObsidianInWord.exe**를 실행합니다.
3. 앱에서 **Word 연결 설정**을 누릅니다. 처음 한 번 현재 Windows 사용자에게 로컬 연결용 인증서와 Word 추가 기능을 등록합니다. 인증서 신뢰 확인창이 뜨면 내용을 확인하세요.
4. **Word 열기**를 누르고 Word의 **홈 또는 삽입 → 추가 기능 → 내 추가 기능**에서 **Obsidian in Word (Windows)**를 엽니다. 목록에 보이지 않으면 문서를 저장하고 Word를 다시 시작하세요.

Windows x64용 휴대용 앱에 편집기가 포함되어 있어 Node.js나 npm 설치가 필요 없습니다. Word 작업창을 사용하는 동안 앱을 실행해 두세요. 앱 창을 닫으면 알림 영역에 남습니다. Microsoft의 Office.js 로드와 커뮤니티 플러그인 조회·다운로드에는 인터넷 연결이 필요합니다. [연결 상태·등록 해제 안내](native/windows-host/README.md)

## 문서 편집하기

Word에서 편집할 텍스트를 **범위로 선택**하고 **선택 영역 → 마크다운**을 누릅니다. 작업창에서 내용을 고친 뒤, 바꾸려는 범위에 맞춰 적용합니다.

| 버튼 | 언제 사용하나요? |
| --- | --- |
| **한 문단만 적용** | 표와 도형까지 함께 불러왔지만 설명 문장 하나만 고쳤을 때 사용합니다. 선택 영역 안에서 하나로 식별되는 일반 텍스트 문단만 교체합니다. WordApi 1.6 이상이 필요합니다. |
| **Word에 적용** | 제목·목록·수식·표 또는 여러 문단을 편집했을 때 사용합니다. 현재 선택 영역 전체를 작업창 내용으로 교체합니다. |

**미적용 초안이 있을 때** 새 영역을 불러오면 교체 여부를 묻습니다. **편집 중 Word 원문이 바뀌었을 때** WordApi 1.6 이상에서는 전체 적용 전에 바뀐 문단을 알려줍니다. 다른 문단의 변경을 살리려면 취소하고 **한 문단만 적용**을 사용하세요. 이 검사는 문단 텍스트를 비교하며 글꼴·색만 바뀐 경우는 감지하지 않습니다.

**되돌리기는 Word의 Ctrl+Z**를 사용합니다. 전체 적용은 여러 Word 작업으로 나뉠 수 있습니다. 적용 도중 실패했다면 문서 상태를 확인하면서 적용 전까지 여러 번 되돌리세요.

## 표·그림·수식은 어떻게 편집하나요?

| 작업창에 보이는 내용 | 편집 방법 |
| --- | --- |
| **Word 표 · 편집 가능** | 아래의 마크다운 표에서 셀 내용을 수정합니다. |
| **Word 원본 표**, **Word 부동 개체** | 수식이 든 복합 표나 떠 있는 도형처럼 원본을 유지하는 개체입니다. 이름을 클릭하면 원본 마커와 ID를 볼 수 있습니다. 개체를 유지하려면 마커도 유지하세요. |
| `$…$`, `$$…$$` | 인라인·블록 수식의 LaTeX를 고칩니다. 앱이 만든 수식 그림도 다시 불러와 편집할 수 있습니다. 수식을 포함한 표 전체를 **Word 원본 표**로 불러온 경우에는 표와 내부 수식을 함께 보존합니다. |
| `[[위키링크]]` | Word에서도 위키링크 표기를 텍스트로 유지합니다. |

원본 개체 데이터는 문서 안에 저장되므로 다른 영역을 편집한 뒤에도 다시 사용할 수 있습니다. 출처를 알 수 없는 일반 그림에서 LaTeX를 추출하는 기능은 제공하지 않습니다. [개체 식별·보존 규칙](docs/object-model.md)

### 수식 출력 선택

**설정 → 옵션 → 수식 출력**에서 고릅니다.

- **Word 수식 우선**(기본)은 변환 가능한 LaTeX를 Word에서 직접 편집할 수 있는 수식으로 넣습니다. 변환이 어려우면 그림을 시도하며, 그림으로도 만들 수 없으면 원본 LaTeX와 경고를 남깁니다.
- **모두 그림**은 수식을 PNG로 넣습니다. 기본 MathJax TeX 글꼴을 쓰거나 **Word 크기·색 + 문서 글꼴 우선**을 선택할 수 있습니다. 문서 글꼴 우선은 적용 시 선택 영역의 통일된 서식을 읽으며, 해당 글꼴에 없는 기호는 수학 글꼴로 표시될 수 있습니다. [문서 글꼴·정렬 검증](docs/testing/2026-11-24-document-font-probe.md)

## 커뮤니티 플러그인과 기존 설정

**설정 → 커뮤니티 플러그인 → 공식 목록 불러오기**에서 플러그인을 검색하고 다운로드합니다. 최신 작업창은 별도 도우미 없이도 다운로드할 수 있습니다. Windows 앱 연결이 있으면 GitHub에서 직접 받고, 연결이 없으면 공개 릴리스 파일을 gh-proxy.com을 통해 받아 GitHub가 제공한 SHA-256과 크기를 대조합니다. 검증값이 없는 이전 릴리스에는 Windows 앱 연결이 필요합니다. 설치한 플러그인은 목록에서 직접 켭니다. 편집 명령과 스니펫은 작업창 에디터에서 동작하며, 호환 범위는 플러그인이 사용하는 Obsidian API에 따라 달라집니다. [플러그인 호환 범위](docs/plugin-compat.md)

기존 웹 작업창에서 Windows 앱으로 옮길 때는 **플러그인·옵션 내보내기**로 JSON을 저장한 다음, 기존 작업창을 닫고 Windows 앱 작업창에서 **이관 파일 가져오기**를 누르세요. 같은 ID로 설치된 플러그인은 기존 설정을 유지하고, 새로 가져온 플러그인은 꺼진 상태로 추가됩니다. JSON에는 플러그인 설정의 인증정보가 포함될 수 있습니다. GitHub Pages는 마지막 웹 배포본으로 유지되며 새 Windows 빌드는 위의 Actions에서 받습니다. [이관 범위와 검증](docs/testing/2026-11-13-settings-transfer.md)

## 개발과 검증

저장소 루트에서 다음 명령을 실행합니다.

```sh
npm ci
npm test
npm run build
```

- **로컬 작업창 개발** — `certs/localhost.key`와 `certs/localhost.crt`에 신뢰된 개발용 인증서를 준비하고 `npm run dev`를 실행한 뒤 [개발용 매니페스트](manifest.xml)를 Word에 등록합니다.
- **실제 Word 회귀 검사** — Windows 데스크톱 Word와 Office 개발 인증서를 준비한 뒤 `npm run test:word`를 실행합니다. 검사기는 자체 테스트 문서를 사용합니다. [사전 설정과 개별 검사 명령](scripts/word-host/README.md)
- **Windows 앱 빌드** — 편집기 번들을 만든 뒤 .NET으로 Windows x64 EXE를 빌드합니다. [Windows 앱 개발 안내](native/windows-host/README.md) · [CI 워크플로](.github/workflows/windows-build.yml)

현재 제품의 편집 방식은 작업창에서의 수동 변환입니다. Word 본문에서 커서 이동에 따라 마크다운과 Word 표현을 자동 전환하는 기능은 후속 개발 항목입니다. [구현 계획](docs/implementation-plan.md) · [로드맵](docs/roadmap.md) · [검증 기록](docs/testing/)

Microsoft 및 Obsidian과 무관한 비공식 개인 프로젝트입니다. Word와 Obsidian은 각 소유자의 상표입니다.
